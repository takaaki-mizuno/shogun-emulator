# フェーズ 4: PPU（スプライトとスクロール）

- 作成日: 2026-09-21
- 前提フェーズ: 3
- 完了条件: `sprite_hit_tests_2005.10.05` の 11 ROM、`sprite_overflow_tests` の 5 ROM、`oam_read`、`oam_stress` が合格する

## 1. 背景

フェーズ 3 で背景が描画できる。ここにスプライトを加える。

スプライト評価には実機のバグがある。8 個見つかった後の 9 個目の探索で OAM を斜めに走査し、タイル番号・属性・X 座標を Y 座標として評価してしまう。この結果、オーバーフローフラグに偽陽性と偽陰性が生じる。**このバグを再現しないと、オーバーフローフラグをタイミング源に使うゲームが動かない。**

スプライト 0 ヒットは多くのゲームが画面分割のタイミング源に使う。発生位置が 1 ドットずれると画面が崩れる。

## 2. 方針とその理由

### 2.1 スプライト評価を仕様どおりのステートマシンとして書く

「範囲内のスプライトを先に 8 個集める」という結果だけを実装しない。設計書 04 編 §4.7 の手順 1 から 4 を、`n`・`m`・`writeDisable`・`phase` を持つステートマシンとして書く。

理由: 結果だけを実装するとオーバーフローバグが再現されない。加えて、レンダリング中の `$2004` の読み出しが「評価が参照している値」を返す挙動も表現できない。

### 2.2 `sprite0OnNext` と `sprite0OnCurrent` の 2 つのフラグを持つ

スプライト 0 が範囲内と判定されたとき `sprite0OnNext` を立て、スキャンラインの開始時に `sprite0OnCurrent` へ移す。

理由: 次行の評価が動いている最中に現在行のヒット判定が走る。1 つのフラグで兼用すると、評価が現在行の判定を壊す。

### 2.3 スプライトフェッチのダミーフェッチもバスに出す

範囲内のスプライトが 8 個未満のとき、残りのスロットでタイル `$FF` へのフェッチを行い、結果を捨てる。このフェッチでも `NotifyPPUAddress` を呼ぶ。

理由: フェーズ 8 の MMC3 がこの通知回数を数える。8×16 スプライトで背景とスプライトが同じパターンテーブルを使う場合、このダミーフェッチが IRQ のカウントに影響する。

### 2.4 優先度の選択順序を守る

スプライト同士の優先度を先に決め、その後で背景との比較を行う。

理由: この順序により「背面指定の若いスプライトが前面指定の後続スプライトより先に選ばれる」挙動が再現される。逆にすると、実機で背景が前面スプライトの前に出るケースが再現されない。

### 2.5 OAM DMA を前倒しで実装する

`$4014` の転送をこのフェーズで実装する。停止のサイクル・位相合わせの 1 サイクル・256 回の転送までを入れる。get/put の位相の細部、DMC DMA との競合、停止中のレジスタ再読み出しは DMA を精密化するフェーズで扱う。

理由: スプライトのテスト ROM は OAM を `$4014` で埋める。`sprite_overflow_tests` は `$2004` を一度も使わない。転送が無いと OAM が空のままで、スプライトの検証が何もできない。
