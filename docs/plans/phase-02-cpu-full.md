## 1. 背景

フェーズ 1 で公式命令が動く。残る 105 個の opcode（非公式命令）と、割り込みの細かいタイミングを実装する。

非公式命令は市販ゲームが実際に使っている。Disney's Aladdin が SLO、Super Cars が LAX、Puzznic が 2 バイト NOP を使う。ある多カートは XAA まで正しく実装しないとリセットハンドラに到達しない。したがって「使われないから省く」という判断はできない。

割り込みの細部（1 命令遅延、ハイジャック、分岐命令のポーリング点）は、フェーズ 3 以降の PPU の NMI と、フェーズ 8 のマッパー IRQ の前提になる。ここで固めておかないと、後のフェーズで「PPU が悪いのか CPU が悪いのか」の切り分けができない。

`cpu_interrupts_v2` は APU のフレーム IRQ と PPU の NMI を割り込み源に使うため、このフェーズでは実行できない。代わりに擬似バスでサイクルを指定して割り込み線を動かす単体テストで検証する。

## 2. 方針とその理由

### 2.1 非公式命令を既存の部品の組み合わせとして実装する

新しいアドレッシングモードや新しい演算をほとんど追加しない。SLO は「`ASL` してから `ORA`」、DCP は「`DEC` してから `CMP`」として、フェーズ 1 で作った `rmw` と既存の演算を組み合わせる。

理由: 非公式命令は実機でも「無関係な複数のマイクロコード行が同時に起動した結果」である。組み合わせとして実装すると、サイクル数が自動的に正しくなる。個別に書くとサイクル数の誤りが入り込む。

### 2.2 安定な命令と不安定な命令を分けて実装する

安定な命令（SLO・RLA・SRE・RRA・SAX・LAX・DCP・ISB・ALR・ANC・ARR・AXS・各種 NOP）を先に実装し、`instr_test-v5/rom_singles/` を通す。不安定な命令（XAA・LAX#・TAS・AHX・SHX・SHY・LAS）を後で実装する。

理由: 安定な命令だけで大半の ROM が合格まで到達するため、先に確実な部分を固める。

### 2.3 不安定な命令を実行したらログに残す

`warn.compat` カテゴリに opcode と PC を記録する。

理由: 実機でも値が定まらない命令に到達したことは、ROM の挙動を調べるときに重要な情報になる。黙って実行すると、後で「なぜ画面が壊れるか」を追えなくなる。

### 2.4 STP で無限ループにしない

`halted` フラグを立て、以降は PC のリードのみを行う。デバッガに「STP により停止」と表示できる状態にする。

理由: 無限ループにするとアプリケーションが応答しなくなり、原因が分からない。

### 2.5 割り込みのポーリング点をサイクル列の中に明示する

各サイクルの終わりにポーリング結果を求め、1 サイクル分ずらして保持する。命令が終わった時点で「最後から 2 番目のサイクルの終わり」の結果がそこに残る。分岐命令は例外として個別に扱う。

理由: アドレッシングモードごとにポーリング点を書き込むと、命令の種類だけ書き漏らす箇所が増える。1 サイクルずらして保持する形にすれば、位置の指定が 1 箇所で済む。

### 2.6 ニモニックは nestest.log の表記に合わせる

`mnemonic` には nestest.log と同じ名前を入れる。NESdev Wiki の `ISC` に対して nestest.log は `ISB` を使うため、`mnemonic` を `ISB`、`alias` を `ISC` とする。

理由: トレースを nestest.log と行単位で比較することが CPU の検証手段である。命令欄の桁数に別名を併記する余裕はない。逆アセンブラは別名を `alias` から取る。

## 6. つまずきやすい点

| 点 | 対処 |
|---|---|
| `ARR` のフラグ | C は bit 6、V は bit 6 XOR bit 5。`ROR` と異なる |
| `AXS` の V フラグ | 変更しない。`CMP` のロジックを流用するため |
| 不安定な命令の定数 `$EE` | `docs/research/02_cpu_6502.md` の 7.3 節の記述を確認する |
| `IGN d,X` が 2 箇所を読むこと | `d` と `(d+X)&$FF` の両方 |
| 分岐命令のポーリング点 | 3 箇所のうち 1 箇所だけポーリングしない |
| `cpu_interrupts_v2` の失敗 | `rom_singles/` を個別に実行し、どのサブテストが失敗するか特定する |
| テスト ROM が結果を返さない | `$6000` プロトコルを使わない ROM がある。シグネチャが現れるかを先に確かめる |
| `$AB`（LAX #i）の動作 | 内部定数が `$FF` として観測される。即値がそのまま A と X に入る |
