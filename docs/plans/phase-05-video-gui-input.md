# フェーズ 5: 映像出力・GUI 最小構成・入力

- 作成日: 2026-09-21
- 前提フェーズ: 4
- 完了条件: メニューから NROM の ROM を開き、キーボードで操作して遊べる（音は出ない）

## 1. 背景

フェーズ 4 までで画面の内容が正しく生成される。ここで初めて画面に出し、操作できるようにする。

このフェーズまで GUI を作らないのは、GUI があると「画面が変だがエミュレータが悪いのか描画が悪いのか」の切り分けが増えるためである。フェーズ 3 と 4 でフレームハッシュによる検証を済ませてあるので、ここで画面に出たものが違っていれば原因は描画側にあると判断できる。

Fyne の描画性能と `fyne.Do` のスレッドモデルは技術検証済みである（`docs/research/09a_fyne_performance_spike.md`）。検証コードは `tools/spikes/` にある。

## 2. 方針とその理由

### 2.1 エミュレーションを専用ゴルーチンで動かし、UI から分離する

エミュレーションゴルーチンは共有構造体へ書くだけとし、UI スレッドが自身の描画周期で読む。エミュレーションゴルーチンから UI を操作しない。

理由: Fyne v2.8 は UI オブジェクトをメインゴルーチン以外から操作すると警告を出し、次のメジャーリリースで安全網が外れる。加えて、押し出し方式にするとエミュレーションが UI の描画速度に引きずられる。

### 2.2 `fyne.Do` の呼び出しを 1 ファイルに閉じる

`internal/ui/dispatch.go` のみが `fyne.Do` と `fyne.DoAndWait` を呼ぶ。フェーズ 0 で入れた静的検査がこれを強制する。

理由: 呼び出しが散ると、Fyne v3 への移行時に全箇所を洗い直すことになる。

毎フレームの画面更新には `fyne.Do` を使わない。Fyne は終了処理が始まった後、渡した関数を呼び出し元のゴルーチンで実行する。自前のゴルーチンからタイマーで更新すると、終了と更新が重なったときに UI オブジェクトを UI スレッド以外から触る。画面の更新は Fyne のフレーム駆動に載せる（設計書 10 編 §10.4）。

### 2.3 このフェーズではオーディオを繋がない

進行の駆動を `Pacer` として分け、壁時計でフレーム周期を待つ実装を置く。オーディオの消費で待つ実装はフェーズ 6 で加える。

理由: オーディオを同時に入れると、画面が出ない原因の候補が増える。

壁時計で待つ実装は、オーディオを無効にしたときとデバイスの初期化に失敗したときに、フェーズ 6 以降も使い続ける（設計書 02 編 §2.6）。当初は「暫定の実装をフェーズ 6 で置き換える」計画であったが、オーディオが無い場合の進行を決めるものが他に無いため、恒久の実装として設計書に位置づけた。

音を出しているあいだ壁時計で待つと、ホストの時計とオーディオデバイスのクロックのずれが累積して音が途切れる。オーディオが有効なときは必ずオーディオ側の実装を使う。この理由を `pacing.go` の先頭に書く。

### 2.4 入力を strobe 時に読む

フレーム単位のスナップショットを取らず、`$4016` への strobe 書き込み時に共有ビットマスクを読む。

理由: 1 フレーム内に複数回ポーリングするプログラムの挙動が実機と一致する。

### 2.5 ビューアの配置を切り替えられる構造を最初から入れる

このフェーズではメイン画面しか作らないが、`Viewer` インタフェースと `ViewerHost`（`windowHost` と `dockedHost`）の骨組みを用意する。

理由: フェーズ 11 でビューアを 4 つ以上追加する。そのときに配置の仕組みを入れると、各ビューアを書き直すことになる。

## 6. つまずきやすい点

| 点 | 対処 |
|---|---|
| DMC DMA と競合するプログラムで入力が 1 bit 欠ける | `$4016` の読み出しと DMC DMA の停止サイクルの競合はフェーズ 7 で扱う。`read_joy3` の該当サブテストはそこで合格させる |
| Fyne の警告が大量に出る | `fyne.Do` を経由していない箇所がある。警告のスタックトレースで箇所を特定する |
| 画面が更新されない | `Refresh()` を呼んでいるか、`image.RGBA` の内容が実際に変わっているかを確認する |
| フレームレートが 60 に届かない | 暫定の進行制御の待ち時間を確認する。`time.Ticker` は負荷でティックを落とす |
| キーが押しっぱなしになる | キーリピートの扱いを確認する |
