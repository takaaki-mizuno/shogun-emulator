# フェーズ 13: 配布

- 作成日: 2026-09-21
- 前提フェーズ: 12
- 完了条件: CI がタグを契機に 3 OS の成果物を生成し、各 OS で成果物を起動して動作する

## 1. 背景

project.md は「シングルバイナリとして配布でき、MacOS / Windows / Linux で動作するようにする。アイコンは後で付けるので、いったんプレースホルダで」を要求している。

「シングルバイナリ」の解釈について人間の判断を得ている。**OS 標準ランタイムへの依存は許容する。** Fyne が必要とする OpenGL と X11 / Wayland、oto が必要とする PulseAudio または ALSA は、デスクトップ環境に事実上必ず存在するものとして扱う。WebView への依存は発生しない（Fyne を選定したため）。

各 OS のネイティブ環境でビルドする。Fyne が OpenGL のバインディングで cgo を用いるため、クロスコンパイルに依存しない。

## 2. 方針とその理由

### 2.1 CI で各 OS のネイティブビルドを行う

クロスコンパイルを使わない。

理由: cgo を使うため、クロスコンパイルには各 OS 向けのツールチェーンが必要になる。CI のランナーを使えば確実で、開発者が手元で再現できる。

### 2.2 アイコンの生成物をリポジトリへ格納する

原本（SVG と 1024 px PNG）から `.icns` と `.ico` を生成し、生成物もコミットする。

理由: ビルド環境に `iconutil` などのツールを要求しない。macOS 以外のランナーでも `.icns` を含むビルドができる。

### 2.3 署名と公証を当面行わない

macOS の Gatekeeper と Windows の SmartScreen の警告について、回避手順を配布物の文書に記載する。

理由: Apple Developer Program（年額）と EV 証明書（年額）の費用が発生する。これは人間の判断を要する。第 1 弾の配布では警告を受け入れ、手順を示す。

### 2.4 Linux で AppImage を併せて提供する

実行ファイル単体と AppImage の両方を配布する。

理由: AppImage は「1 ファイルでダブルクリック起動」となり、project.md の「シングルバイナリとして配布」の意図に最も近い。実行ファイル単体も残すのは、パッケージマネージャ経由の導入や自動化での利用を想定するためである。

### 2.5 タグを契機にリリースする

`v` で始まるタグを打ったときに成果物をリリースへ添付する。

理由: バージョン情報がバイナリに埋め込まれるため、タグと成果物の対応が明確になる。

| 点 | 対処 |
|---|---|
| macOS で Dock にアイコンが出ない | `.app` バンドルになっているか確認する。単体のバイナリでは出ない |
| macOS でメニューバーが出ない | 同上 |
