## 1. 背景

フェーズ 5 から 11 まで、設定値は構造体リテラルの既定値を使ってきた。ここで設定ファイルの読み書きと設定 GUI を実装し、CLI の全オプションを揃える。

project.md は「設定などは、各 OS で最も適切な場所に JSON の設定ファイルとして保存する」「コマンドラインでも起動が可能。その際には設定を各種引数で更新できる」「キーバインディングの変更ができる。GUI としても提供され、設定ファイルとして保存される」を要求している。

## 2. 方針とその理由

### 2.1 パス解決を 1 箇所にまとめる

`config.ResolvePaths` が設定・データ・キャッシュ・ログ・スクリーンショットのディレクトリを返す。各パッケージが `os.UserConfigDir` を直接呼ばない。

理由: ポータブルモードと CLI による上書きを 1 箇所で扱える。OS ごとの差（Linux のデータディレクトリに標準関数がない）もここに閉じる。

### 2.2 サンプリングレートを設定項目から外す

48000 Hz に固定する。バッファ長のみを設定項目とする。

理由: `oto.NewContext` をプロセスで 1 回しか呼べない。レートを設定項目にすると「変更には再起動が必要」という扱いが必要になり、利用者に負担をかける。内部で固定すれば制約が表に出ない。

### 2.3 未知のフィールドを無視し、`version` が新しいときは既定値で起動する

前方互換を保つが、明らかに読めない場合は安全側に倒す。

理由: 新しいバージョンで書かれた設定を古いバージョンが部分的に読むと、想定しない組み合わせで動作する。

### 2.4 設定の保存を一時ファイル経由にする

一時ファイルへ書いて `rename` する。

理由: 書き込み中の異常終了で設定を失わない。

### 2.5 キーバインドの取り込み中はホットキーを止める

キーを割り当てる操作の間、ホットキーの処理を無効にする。

理由: `F5` を割り当てようとしたときにセーブステートが実行されると、割り当てができない。

## 6. つまずきやすい点

| 点 | 対処 |
|---|---|
| Linux で設定の場所が違う | `$XDG_CONFIG_HOME` と `$XDG_DATA_HOME` を区別する。データには標準関数がない |
| `F5` を割り当てられない | 取り込み中にホットキーを止めているか確認する |
| Windows で `--version` の出力が見えない | `AttachConsole` の呼び出しと標準出力の差し替えを確認する |
| 設定を保存したら壊れた | 一時ファイルへ書いて `rename` しているか確認する |
| サンプリングレートを変えても効かない | 48000 に固定している。設計上の判断である |
| 設定変更が反映されない | 即座に反映する項目と ROM の再読み込みが必要な項目の区別を確認する |
