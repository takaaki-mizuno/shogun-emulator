# フェーズ 11: デバッガ（PPU 系ビューアと編集）

- 作成日: 2026-09-21
- 前提フェーズ: 10
- 完了条件: パターンテーブル・ネームテーブル・スプライト・パレットの 4 ビューアが実時間でメモリと同期し、編集した内容が画面に反映される

## 1. 背景

project.md が要求する「スプライト、BG、パレットを視覚的に見る別ウィンドウ」と「その場で書き換えるエディタ」を実装する。

この 4 ビューアは PPU のデバッグで実際に必要になる。PPU のバグは画面を見ても原因が分からず、中間状態（どのタイルがどのパレットで描かれているか、どのスプライトが評価されたか）を見る必要がある。

編集機能には CHR-ROM の扱いという課題がある。CHR-ROM は実機では書き込めない。オーバーレイ層を用意して、ROM ファイルを書き換えずに編集を実現する。

## 2. 方針とその理由

### 2.1 ビューアを配置形態から独立させる

各ビューアを `Viewer` インタフェースの実装とし、別ウィンドウに置かれるかタブに置かれるかを知らない構造にする。

理由: 設定 `ui.viewerLayout` で配置を切り替えられるようにするため。ビューアが配置を知っていると、切り替えのたびに各ビューアを直すことになる。骨組みはフェーズ 5 で用意済みである。

### 2.2 ROM ファイルを書き換えない

編集内容をオーバーレイ層に保持し、別ファイルへ保存する。

理由: ROM を直接書き換えると、元に戻せず、ROM ハッシュが変わってセーブデータと紐付かなくなる。利用者から見れば「エミュレータが自分の ROM を壊した」ことになる。

### 2.3 オーバーレイを有効・無効で切り替えられるようにする

無効にすれば実機どおりの動作を確認できる。

理由: 編集して動作を試した後、元の挙動と比べる必要がある。

### 2.4 任意スキャンラインのスナップショットを提供する

MMC3 などがスキャンラインごとに CHR バンクを切り替える場合、フレーム末の状態は画面の一部しか表さない。指定スキャンラインでスナップショットを取れるようにする。

理由: ステータスバーと本体で異なる CHR バンクを使うゲームが多い。フレーム末の状態だけでは、本体側のタイルが見えない。

### 2.5 パターンテーブルの既定の表示をグレースケールにする

パレットを適用せず、4 階調で表示する。

理由: タイルの形を確認するのが主な用途である。パレットを適用すると、透明色と背景色が同じで形が見えないことがある。

## 6. つまずきやすい点

| 点 | 対処 |
|---|---|
| パターンテーブルの内容が画面と合わない | 現在のバンク構成を反映しているか確認する。`cart.Info()` の `CHRBanks` を使う |
| MMC3 でビューアの内容が画面の一部しか表さない | 任意スキャンラインのスナップショットを使う。これは正しい挙動である |
| スクロール枠の位置がずれる | `v` の coarse X / Y と `x`（fine X）から計算する。`t` ではない |
| ネームテーブルのミラーが反映されない | `MapNametable` を通しているか確認する |
| CHR-ROM を編集しても変わらない | オーバーレイが有効か確認する |
| 編集が次回起動で消える | `patches/<rom-hash>.json` への保存を確認する |
| ビューアを開くとフレームレートが落ちる | スナップショットのコピー量と更新頻度を確認する |
