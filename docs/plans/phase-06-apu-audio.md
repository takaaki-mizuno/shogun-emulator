# フェーズ 6: APU とオーディオ出力

- 作成日: 2026-09-21
- 前提フェーズ: 5
- 完了条件: `apu_test`・`blargg_apu`・`apu_reset`・`apu_mixer` が合格し、10 分間の連続再生で音切れが発生しない

## 1. 背景

APU の 5 チャンネルを実装し、実際に音を出す。あわせてフェーズ 5 で暫定実装した進行制御を、オーディオデバイスの消費を駆動源とするバックプレッシャ方式へ置き換える。

進行制御の置き換えは必須である。壁時計のティッカーで駆動する方式は 60 秒間に 137 回の音切れを起こす（`docs/research/09a_fyne_performance_spike.md` の 4.4 節の実測）。±0.5% のフィードバック補正を足しても 6 回残る。バックプレッシャ方式では 0 回になり、CPU 負荷を 10 倍にしても崩れない。

## 2. 方針とその理由

### 2.1 バックプレッシャ方式に置き換える

エミュレーションゴルーチンはリングバッファが高水位に達したら `sync.Cond` でブロックし、oto の再生スレッドが消費したときに起きる。壁時計を参照しない。

理由: 上記の実測により、この方式のみが音切れを 0 にする。加えて壁時計を使わないことで決定論が保たれ、フェーズ 9 の入力ムービーが成立する。

### 2.2 リングの高水位を oto のバッファの 2 倍にする

設定で変更できるが、2 未満を指定したときは 2 に丸める。

理由: 等倍では余裕がなく、一時的な処理の遅れがそのまま音切れになる（実測で重負荷時に音切れが発生）。3 倍では余裕が過剰でレイテンシだけが増える。

### 2.3 部品を型として分けて実装する

分周器・エンベロープ・レングスカウンタ・スイープを個別の型にし、各チャンネルが組み合わせて持つ。

理由: 部品ごとに単体テストを書ける。エンベロープやスイープの挙動が誤っているとき、どの部品の問題かが直接分かる。

このフェーズを始めてから、`test_apu_env`・`test_apu_sweep`・`test_apu_timers`・`test_tri_lin_ctr`・`square_timer_div2`・`apu_phase_reset`・`test_apu_2` が取得できないことが分かった（設計書 12 編 §12.6.1）。これらが見るはずだった挙動は、部品ごとの単体テストと、波形の周波数を測るテストで確かめる。部品を分けておいたことがそのまま代わりの検証手段になる。

### 2.4 ミキサーをルックアップテーブルで実装する

非線形の式をそのまま毎サンプル計算せず、31 エントリと 203 エントリのテーブルを起動時に作る。

理由: 毎サンプル 2 回の除算を避ける。加えて非線形性を保つ。DMC のレベルが Triangle と Noise の音量に影響する挙動をゲームが利用している。

### 2.5 `oto.NewContext` をプロセスで 1 回だけ呼ぶ

サンプリングレートを 48000 Hz に固定し、設定 GUI から変更できない項目とする。バッファサイズは `Player.SetBufferSize` で実行中に変更する。

理由: `oto.NewContext` の 2 回目の呼び出しは `oto: context is already created` で失敗する（実測）。レートを固定すればこの制約が表に出ない。

### 2.6 チャンネルを 1 つずつ完成させる

Pulse 1 → Pulse 2 → Triangle → Noise → DMC の順に実装し、各段階で対応するテスト ROM を通す。

理由: 5 チャンネルを同時に書くと、音が変なときに原因のチャンネルが特定できない。

## 6. つまずきやすい点

| 点 | 対処 |
|---|---|
| Triangle のタイマーが 2 倍速い・遅い | CPU サイクルごとにクロックする。Pulse と異なる |
| Pulse の最低オクターブが鳴らない | 目標周期が `$7FF` を超えるとスイープ無効でもミュートされる。正しい挙動である |
| Pulse 1 と Pulse 2 でスイープの結果が違う | 1 の補数と 2 の補数の違い。実装が入れ替わっていないか確認する |
| `$4017` 書き込みの遅延 | 3 サイクルと 4 サイクルの判定条件を確認する |
| 音が途切れる | リングの高水位が oto バッファの 2 倍以上か確認する。プライミングを行っているか確認する |
| 起動時に無音が入る | 再生開始前にリングを高水位まで埋める |
| `oto: context is already created` | `NewContext` を 1 回しか呼んでいないか確認する |
