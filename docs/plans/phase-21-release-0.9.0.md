# フェーズ 21: リリース 0.9.0（アイコンの刷新とインストーラ）

- 作成日: 2026-10-07
- 前提フェーズ: 13
- 完了条件: 新しいアイコンから各 OS 向けの形式を生成でき、アプリ内でロゴとして表示され、`tools/package` が macOS の `.dmg`（背景と配置つき）・Windows の `.msi`・Linux の `.deb` と `.rpm` を作り、`v0.9.0` のタグでリリースの下書きにすべての成果物が並ぶ

## 1. 背景

フェーズ 13 で配布の仕組みを作った。アイコンは「将」の字から生成した仮のもので、Windows はインストーラが無く `.zip` だけを配っていた。最初の公開版 0.9.0 に向けて、次の 3 点をそろえる。

| 項目 | 内容 |
|---|---|
| アイコン | 原画 `assets/icon.png` を唯一の原本とし、各 OS 向けの形式とアプリ内のロゴを作る |
| インストーラ | macOS は `.dmg` を改良し、Windows は `.msi`、Linux は `.deb` と `.rpm` を加える |
| リリース | 版を `v0.9.0` とし、リリースノートをリポジトリに置く |

## 2. 方針とその理由

### 2.1 アイコンの原本を原画 1 枚にする

`tools/gen-icon` から字形の生成を外し、`assets/icon.png` から各形式を作るだけにする。

理由: 図柄が字形から作るものではなくなった。原本が 2 つあると、どちらが正しいかが分からなくなる。

### 2.2 macOS だけ角丸のタイルにする

`.icns` は 1024 px の枠に 824 px の角丸の正方形を置く形にする。`.ico` と Linux の PNG は原画をそのまま縮小する。

理由: macOS 11 以降のアイコンは角丸のタイルと余白を持つ形にそろっており、四角いままだと Dock で浮く。Windows と Linux には決まった外形が無く、余白を取ると小さい大きさで図柄がつぶれる。

### 2.3 Windows のインストーラを WiX v5 の `.msi` にする

`.wxs` を `tools/package` が版とアーキテクチャから作り、`wix build` で `.msi` にする。WiX v6 以降は使わない。

理由: `.msi` は企業の配布ツールでも扱える標準の形式である。WiX v6 以降は利用条件に保守費用（OSMF）の規定が加わったため、条件の無い v5 に固定する。

### 2.4 Linux のパッケージを nfpm で作る

`go.mod` の `tool` 指令で nfpm の版を固定し、`go tool nfpm` で `.deb` と `.rpm` を作る。

理由: `dpkg-deb` と `rpmbuild` を両方入れなくても、どの OS でも同じ手順で作れる。`goversioninfo` と同じく、ツールの版をリポジトリで固定できる。

### 2.5 `.dmg` の配置は作れなくても失敗にしない

背景画像とアイコンの配置は Finder の AppleScript で設定する。AppleScript が失敗したときは警告を出し、配置の無い `.dmg` を作る。

理由: Finder の自動操作は画面の無い環境や許可の無い環境で失敗する。配置は見た目だけの問題であり、配布物が作れないほうが困る。

### 2.6 git の操作は人が行う

タグの作成と push は人が行う。このフェーズでは成果物を作る手順とリリースノートまでをそろえる。
