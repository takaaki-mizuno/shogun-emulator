# フェーズ 9: セーブステート・巻き戻し・入力ムービー

- 作成日: 2026-09-21
- 前提フェーズ: 8
- 完了条件: 全フレーム往復テストが対応 7 マッパーで合格し、決定論テスト（同一環境での再現・クロスプラットフォーム）が合格する

## 1. 背景

フェーズ 1 から 8 で、各コンポーネントの `SaveState` / `LoadState` と往復テストは既に書かれている。このフェーズではその上に機能を載せる。

| 機能 | 内容 |
|---|---|
| セーブステート | 10 スロット、クイックセーブ・ロード、名前を付けて保存 |
| 巻き戻し | 直近 60 秒を遡る |
| 入力ムービー | 記録と再生、desync の検出 |

3 機能は共通の基盤（状態直列化と決定論）を使う。巻き戻しは「ステートのロード + 記録した入力での前方再生」であり、ムービー記録の仕組みをそのまま再利用する。

このフェーズで決定論を確定させる。以降のフェーズ（デバッガ、設定 GUI）はエミュレーション結果に影響を与えてはならない。

## 2. 方針とその理由

### 2.1 ヘッダに初期状態と識別情報を含める

ROM ハッシュ・マッパー番号・サブマッパー・リージョン・エミュレータバージョン・`InitState` をヘッダに入れ、ロード時に検証する。

理由: 異なる ROM やマッパーのステートを読み込むと、復元が成立せず原因が分からない異常動作になる。検証して明示的にエラーを返す。

### 2.2 セーブステートのバージョン互換を保証しない

エミュレータバージョンが一致しないステートはエラーとする。

理由: 精度を高めるたびに保存する状態が増える。中途半端に読めてしまい挙動が変わるほうが、読めないより悪い。バッテリーバックアップの `.sav` は単純なバイト列なのでバージョンによらず読める。

### 2.3 ムービーの入力をフレーム単位で記録する

ポーリング単位ではなくフレーム単位とし、ラッチ点を scanline 0 / dot 0 に固定する。

理由: フレーム単位なら編集でき、サイズも小さい。ポーリング単位は忠実だが、再生時にポーリング列が完全一致しないと使えず、編集もできない。実機の strobe 時読み出しの挙動は変わらない。

### 2.4 連射は記録時に適用後の状態を書く

再生時に連射を再適用しない。

理由: 連射はこのアプリケーションの機能であり、実機のコントローラの機能ではない。再生時に再適用すると、記録時と異なる位相で連射が入り desync する。

### 2.5 desync をチェックサムで検出し、既定で停止する

60 フレームごとに状態のハッシュを記録し、再生時に比較する。不一致でフレーム番号と対象を報告して停止する。

理由: 黙って続けると、どこから結果が違ったのか分からなくなる。エミュレーションの挙動を意図して変えたときに、このテストが失敗することで変更の影響範囲が分かる。

### 2.6 巻き戻しのステート保存間隔を 10 フレームとする

毎フレーム保存しない。目標フレームの直前のステートをロードし、記録した入力で前方再生する。

理由: 毎フレーム保存すると 60 秒で 144 MiB を要する。10 フレーム間隔なら圧縮して数 MiB に収まる。前方再生が成立するのは決定論が保証されているためである。

## 6. つまずきやすい点

| 点 | 対処 |
|---|---|
| 往復テストが失敗する | `FirstDiffSection` で示されたコンポーネントの「保存する状態」の表と実装を照合する |
| ムービーが 2 回目の再生で desync する | ホスト側の非決定性。`map` のイテレーション・ゴルーチン・壁時計・グローバル乱数を探す |
| 3 OS でハッシュが一致しない | 浮動小数点の演算がエミュレーション状態に影響している。`math` パッケージの関数の使用箇所を確認する |
| 巻き戻しが元の状態と一致しない | 前方再生で使う入力が記録したものになっているか確認する |
| ステートのロード後に音が途切れる | フィルタのリセットとリングの再プライミングを行っているか確認する |
| 連射がムービーで再現しない | 記録時に適用後の状態を書いているか確認する |
