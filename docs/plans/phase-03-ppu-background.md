# フェーズ 3: PPU（フレームタイミングと背景描画）

- 作成日: 2026-09-21

## 1. 背景

PPU はエミュレータの正確さのほとんどを決める。とくに VBlank フラグと NMI のタイミングは 1 PPU クロックの精度が要求され、ここがずれると多くのゲームが起動しない。

`ppu_vbl_nmi` は 1 PPU クロックの精度でこれを検証する。このテストを先に通し、その上で背景描画を実装する。順序を逆にすると、画面が出ないときに「タイミングが悪いのか描画が悪いのか」の切り分けができない。

スプライトはフェーズ 4 に分ける。背景だけでも `ppu_vbl_nmi` は通り、画面にタイルマップが出る状態まで到達できる。

## 2. 方針とその理由

### 2.1 `v` / `t` / `x` / `w` をそのまま実装する

スクロール位置を `scrollX` / `scrollY` として持たない。設計書 04 編 §4.4.2 のビット転送表をそのままコードにする。

理由: 画面途中でスクロールを変えるゲームは、`$2005` と `$2006` の書き込みによる `t` の部分的な更新に依存する。`scrollX` / `scrollY` で持つ実装はこれを表現できず、後から直すと PPU 全体を書き直すことになる。

### 2.2 フェッチを 2 ドット単位で刻む

1 回の VRAM アクセスを 2 ドットに分け、1 ドット目にアドレスをバスへ出して `NotifyPPUAddress` を呼ぶ。

理由: フェーズ 8 の MMC3 がこの通知回数を数えてスキャンライン IRQ を生成する。後から 2 ドット構成に変えると、フェッチ処理全体を書き直すことになる。

### 2.3 ドット単位の巨大な `switch` を避ける

`Step()` の中に `dot` の値ごとの分岐を並べない。「背景フェッチ区間か」「スプライトフェッチ区間か」を判定する述語と、8 ドット周期の位相で処理を決める構造にする。

理由: 341 通りの分岐を並べると、設計書の表との対応が追えなくなる。区間と位相で表すと、設計書 04 編 §4.5.1 の表と 1 対 1 で対応する。

### 2.4 フレームバッファにパレットインデックスを保持する

RGB へ変換せず、6 bit のパレット値と 3 bit のエンファシスを `uint16` として保持する。

理由: パレットファイルを差し替えられるようにするため。加えて、デバッガでピクセルのパレットインデックスを表示できる。

### 2.5 VBlank フラグの読み出し競合を専用の処理として書く

`$2002` の読み出しがフラグのセットと同一ドットまたは前後 1 ドットに起きた場合の挙動を、条件分岐として明示的に書く。

理由: `ppu_vbl_nmi` の `02-vbl_set_time` と `05-nmi_timing` がこの挙動を検証する。通常の読み出し処理に埋め込むと、条件を取り違えても気づかない。

### 2.6 CPU と PPU のサイクル内の位相を実装する

1 CPU サイクルの間に PPU が進む 3 ドットのうち、CPU のバスアクセスがどの時点で起きるかを設定できるようにする。`InitState.CPUPPUAlignment` から決める。

理由: `ppu_vbl_nmi` の `05-nmi_timing` から `08-nmi_off_timing` は、この位相に 1 ドットの精度で依存する。位相を持たない実装では、VBlank フラグのタイミングを合わせても NMI のタイミングが合わない。

## 6. つまずきやすい点

| 点 | 対処 |
|---|---|
| `ppu_vbl_nmi` の失敗 | `rom_singles/` を個別に実行し、どのサブテストが失敗するか特定する |
| CPU と PPU のアライメント | `ppu_vbl_nmi` の readme に「起動時のクロック分周器の値により一部のテストが失敗する」と記されている。`InitState.CPUPPUAlignment` を 0 に固定して検証する |
| 奇数フレームの 1 ドットスキップ | `09-even_odd_frames` と `10-even_odd_timing` で検証される |
