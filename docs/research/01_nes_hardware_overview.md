# NES / ファミリーコンピュータ ハードウェア全体像

> 調査日: 2026-09-20〜21 / 一次情報源: NESdev Wiki（https://www.nesdev.org/wiki/）
> 本書は各論（02〜08）の入口となる俯瞰図。詳細は各ドキュメントを参照する。

## 1. システム構成

NES（Nintendo Entertainment System）/ ファミリーコンピュータは、3 つの主要チップと 2 つの RAM、カートリッジで構成される。

```
        ┌──────────────────────────────────────────────────────┐
        │                     マスタークロック                  │
        │      NTSC 21.477272 MHz / PAL 26.601712 MHz          │
        └───────────┬──────────────────────┬───────────────────┘
                    │ ÷12 (NTSC)           │ ÷4 (NTSC)
                    ▼                      ▼
    ┌───────────────────────────┐   ┌──────────────────────────┐
    │  RP2A03 / RP2A07          │   │  RP2C02 / RP2C07 (PPU)   │
    │  ┌─────────────────────┐  │   │                          │
    │  │ 6502 コア           │  │   │  内部: OAM 256 B         │
    │  │（10進モードなし）   │  │   │        パレット RAM 32 B │
    │  ├─────────────────────┤  │   │        secondary OAM 32 B│
    │  │ APU（5ch）          │  │   │                          │
    │  ├─────────────────────┤  │   └───┬──────────────┬───────┘
    │  │ OAM DMA / DMC DMA   │  │       │ PPU バス     │
    │  ├─────────────────────┤  │       │ 14 bit       │
    │  │ ジョイパッド I/O    │  │       ▼              │
    │  └─────────────────────┘  │   ┌──────────┐      │
    └──────┬────────────────────┘   │ CIRAM    │      │
           │ CPU バス 16 bit         │ 2 KiB    │      │
           ▼                         │（VRAM）  │      │
    ┌──────────────┐                 └──────────┘      │
    │ 内蔵 RAM     │                                    │
    │ 2 KiB        │                                    │
    └──────────────┘                                    │
           │                                            │
           ▼                                            ▼
    ┌──────────────────────────────────────────────────────────┐
    │              カートリッジ（Game Pak）                     │
    │  PRG-ROM / CHR-ROM / CHR-RAM / PRG-RAM(WRAM)             │
    │  マッパー（バンク切り替え、ミラーリング制御、IRQ、拡張音源）│
    └──────────────────────────────────────────────────────────┘
```

**重要な性質**: CPU と PPU は**完全に独立したアドレスバス**を持つ。CPU は PPU のメモリに直接アクセスできず、$2006/$2007 のレジスタ経由でしか読み書きできない。これが「VBlank 中にしか VRAM を書き換えられない」という NES プログラミングの根本的な制約を生む。

## 2. 各コンポーネントの要約

| コンポーネント | 内容 | 詳細 |
|---|---|---|
| **CPU** | MOS 6502 の第二ソース版（Ricoh 製）。10 進モードなし。NTSC 1.789773 MHz | `02_cpu_6502.md` |
| **PPU** | 256×240 ピクセル、64 色中同時 25 色、BG 1 面 + スプライト 64 個（1 スキャンラインに 8 個まで） | `03_ppu.md` |
| **APU** | Pulse ×2、Triangle、Noise、DMC（DPCM）の 5 チャンネル。非線形ミキシング | `04_apu.md` |
| **カートリッジ** | PRG-ROM / CHR-ROM とマッパー。バンク切り替えでアドレス空間の制約を回避 | `05_cartridge_and_mappers.md` |
| **入力** | 標準コントローラ（8 ボタンのシリアル読み出し）× 2 ポート | `06_input_devices.md` |
| **DMA** | OAM DMA（256 バイト、513/514 サイクル）と DMC DMA（1 バイト、3/4 サイクル） | `07_timing_and_synchronization.md` |

## 3. メモリマップ（要約）

### 3.1 CPU アドレス空間（16 bit）

| 範囲 | 内容 |
|---|---|
| $0000–$07FF | 内蔵 RAM 2 KiB（$0800–$1FFF にミラー） |
| $2000–$2007 | PPU レジスタ（$2008–$3FFF に 8 バイトごとミラー） |
| $4000–$4017 | APU および I/O レジスタ |
| $4018–$401F | 通常無効なテスト機能 |
| $4020–$FFFF | カートリッジ（$6000–$7FFF が WRAM、$8000–$FFFF が PRG-ROM とマッパーレジスタが慣習） |
| $FFFA–$FFFF | 割り込みベクタ（NMI / RESET / IRQ-BRK） |

### 3.2 PPU アドレス空間（14 bit）

| 範囲 | 内容 |
|---|---|
| $0000–$1FFF | パターンテーブル（CHR）。カートリッジ |
| $2000–$2FFF | ネームテーブル 4 枚（物理的には CIRAM 2 KiB をミラー） |
| $3000–$3EFF | $2000–$2EFF のミラー |
| $3F00–$3F1F | パレット RAM（$3F20–$3FFF にミラー） |

### 3.3 PPU 内部メモリ

| メモリ | サイズ | 内容 |
|---|---|---|
| OAM | 256 B | スプライト 64 個 × 4 バイト（DRAM なので減衰する） |
| secondary OAM | 32 B | 現在のスキャンラインのスプライト 8 個 |
| パレット RAM | 32 B | BG 4 組 + スプライト 4 組 × 4 色 |

## 4. クロックとタイミング

| 項目 | NTSC | PAL | Dendy |
|---|---|---|---|
| CPU クロック | 1.789773 MHz | 1.662607 MHz | 1.773448 MHz |
| PPU ドット / CPU サイクル | 3 | 3.2 | 3 |
| 可視スキャンライン | 240 | 239 | 239 |
| フレームあたり CPU サイクル | 29780.5 | 33247.5 | 35464 |
| フレームレート | 60.0988 Hz | 50.0070 Hz | 50.0070 Hz |
| APU フレームカウンタ | 60 Hz | 50 Hz | 59 Hz |

**フレームレートが 60.000 Hz ではなく 60.0988 Hz であること**が、映像とオーディオの同期設計に直接影響する（`07_timing_and_synchronization.md` §6）。

## 5. 1 フレームの流れ

```
scanline 261 (プリレンダー)  ┐ dot 1 で VBlank/sprite0/overflow フラグをクリア
                            │ dot 280–304 で v ← t（垂直スクロール成分）
                            │ 奇数フレームは 1 ドット短い
scanline 0                  ┐
  dot 0        idle         │
  dot 1–256    BG フェッチ + ピクセル出力
  dot 65–256   次の行のスプライト評価（並行）
  dot 257–320  次の行のスプライトタイルフェッチ、OAMADDR = 0
  dot 321–336  次の行の最初の 2 タイルをフェッチ
  dot 337–340  未使用のネームテーブルフェッチ ×2（MMC5 がこれを使う）
  dot 256      v の垂直インクリメント
  dot 257      v ← t（水平スクロール成分）
...
scanline 239                ┘ 可視領域おわり
scanline 240   ポストレンダー（何もしない）
scanline 241   dot 1 で VBlank フラグセット + NMI 発生  ┐
...                                                     │ この 20 スキャンライン
scanline 260                                            ┘ （約 2273 CPU サイクル）
                                                          の間だけ VRAM / OAM を書ける
```

**ゲームプログラムの基本構造**: NMI ハンドラで VRAM 更新 → OAM DMA → スクロール設定 → メインループでゲームロジック。VBlank の約 2273 サイクルに収まらないと画面が乱れる。

## 6. エミュレータ実装に効く「非自明な事実」トップ 10

各論から、実装時に必ず引っかかるものを抜き出した。

1. **6502 の 1 サイクルは必ず 1 回のリードまたはライト。** アイドルサイクルは存在せず、何もしないサイクルでもどこかを読む（ダミーリード）。この読みが PPU レジスタや MMC3 の A12 を叩く → `02_cpu_6502.md` §5.1
2. **RMW 命令（INC/DEC/ASL/LSR/ROL/ROR + 非公式の SLO 等）は 2 回書き込む。** 元の値 → 変更後の値。`INC $2007` は PPUDATA に 2 回書く → `02_cpu_6502.md` §6.1
3. **非公式命令 256 個すべてを実装する必要がある。** 市販ゲームが実際に使っている（Aladdin が SLO、Super Cars が LAX など） → `02_cpu_6502.md` §7
4. **CLI / SEI / PLP による I フラグ変更は 1 命令遅れて効く。RTI は即時。** → `02_cpu_6502.md` §9.2
5. **VBlank フラグのポーリングは信頼できない。** セットされる 1 ドット前に読むとフラグが立たず NMI も抑止される → `03_ppu.md` §4.4
6. **スクロールは v / t / x / w の 4 レジスタで表現しなければならない。** scrollX/scrollY で持つ実装はラスタ効果で必ず壊れる → `03_ppu.md` §4.7
7. **スプライトオーバーフローフラグの検出ロジックにはバグがある。** OAM を「斜めに」スキャンし、偽陽性・偽陰性を出す。この挙動をタイミング源に使うゲームがある → `03_ppu.md` §7.2
8. **MMC3 のスキャンライン IRQ は PPU A12 の立ち上がりを数えている。** スキャンライン番号ではない。8×16 スプライトでは A12 を明示的に追跡する必要がある → `05_cartridge_and_mappers.md` §5.7
9. **DMC DMA が CPU を止めると、停止時に読んでいたアドレスが繰り返し読まれる。** コントローラ読み出しから 1 bit が落ちて「Right が誤入力される」 → `07_timing_and_synchronization.md` §3.6
10. **オープンバスは「直前にバスから読んだ値」を返す。** コントローラポートの上位 3 bit がこれに依存しており、Paperboy などは $41 が返ることを前提にしている → `07_timing_and_synchronization.md` §4.1

## 7. 実装アーキテクチャの決定（各論の結論をまとめる）

| 項目 | 決定 | 根拠 |
|---|---|---|

| PPU | ドット単位 | `03_ppu.md` §12.1 |
| APU | CPU サイクル単位 | `04_apu.md` §9.1 |
| コンポーネント同期 | lock-step（CPU 1 サイクルごとに PPU 3 ドット、APU 1 サイクル） | `07_timing_and_synchronization.md` §7.1 |
| 実時間同期 | オーディオ駆動 + 動的リサンプル | `07_timing_and_synchronization.md` §6.1 |
| マッパー | CPU バスと PPU バスの両方を観測できる interface | `05_cartridge_and_mappers.md` §7.3 |

## 8. パッケージ構成の案

GUI フレームワークの選択が変わっても影響を受けないように、**エミュレータコアを GUI から完全に切り離す。**

```
cmd/shogun/              main。GUI 起動と CLI 起動の分岐
internal/nes/            エミュレータコア（GUI 非依存、テスト可能）
    cpu/                 6502 コア
    ppu/                 2C02
    apu/                 2A03 の音源部
    cart/                iNES/NES 2.0 ローダ、マッパー実装
    input/               コントローラ
    bus/                 バス、DMA、オープンバス
    nes.go               全体の組み立て
internal/emu/            ライフサイクル（ロード、実行、ステップ、セーブステート、速度制御）
internal/debug/          デバッガのロジック（ブレークポイント、逆アセンブラ、トレース）
internal/ui/             GUI 層（フレームワーク依存をここに閉じ込める）
internal/config/         設定ファイル、キーバインド
internal/testrom/        テスト ROM ランナー
assets/                  アイコン、デフォルトパレット（embed する）
docs/                    このドキュメント群
tools/                   ビルド・アイコン生成・テスト ROM 取得スクリプト
```

**この境界を守ることが、フレームワーク選定を間違えたときの保険になる。**

## 9. 用語集

| 用語 | 意味 |
|---|---|
| **PRG-ROM** | プログラム ROM。CPU が実行するコードとデータ |
| **CHR-ROM / CHR-RAM** | キャラクタ ROM/RAM。PPU が読むタイルパターン。"CHR" は character（文字）から |
| **WRAM / PRG-RAM** | カートリッジ上のワーク RAM。$6000–$7FFF。バッテリーバックアップされることが多い |
| **CIRAM** | 本体内蔵の 2 KiB VRAM。ネームテーブルに使われる |
| **OAM** | Object Attribute Memory。PPU 内部のスプライト情報 256 バイト |
| **ネームテーブル** | BG のタイル配置（32×30 タイル = 960 バイト）+ 属性テーブル（64 バイト） |
| **属性テーブル** | 16×16 ピクセルごとにパレット番号を指定する 64 バイト |
| **パターンテーブル** | タイルのビットマップ。1 タイル 16 バイト（2 プレーン × 8 バイト） |
| **マッパー** | カートリッジ上のバンク切り替え等の回路。iNES 形式では番号で識別する |
| **MMC** | Memory Management Controller。Nintendo 製 ASIC マッパーの呼称 |
| **VRC** | Virtual ROM Controller。Konami 製 ASIC マッパーの呼称 |
| **ミラーリング** | 不完全なアドレスデコードにより同じメモリが複数のアドレスに現れること。ネームテーブルミラーリングは意図的なもの |
| **オープンバス** | どのデバイスも応答しないアドレスを読んだときの値。直前にバスにあった値が返る |
| **バス競合（bus conflict）** | 2 つのデバイスが同時にバスに値を出すこと。ディスクリートマッパーへの書き込みで起こる |
| **VBlank** | 垂直ブランキング期間。PPU が描画していない期間で、VRAM を書き換えられる |
| **HBlank** | 水平ブランキング期間 |
| **dot / tick** | PPU の 1 クロック。1 ピクセルに対応 |
| **スキャンライン** | 水平 1 行。NTSC で 341 ドット |
| **プリレンダー行** | scanline 261（= −1）。次の行の準備をするダミー行 |
| **fine X / fine Y** | タイル内のピクセル位置（0–7） |
| **coarse X / coarse Y** | タイル単位の位置 |
| **sprite 0 hit** | スプライト 0 と BG の不透明ピクセルが重なったこと。画面分割のタイミング源に使われる |
| **DPCM** | Delta PCM。DMC チャンネルが再生する 1 bit デルタ符号化サンプル |
| **oops サイクル** | インデックス付きアドレッシングでページ境界をまたいだときの余分なリード |
| **lock-step** | コンポーネントを 1 サイクルずつ交互に動かす同期方式 |
| **catch-up** | 1 つのコンポーネントを先に進め、後から他を追いつかせる同期方式 |
