# 入力デバイス（コントローラ）調査

> 調査日: 2026-09-20 / 一次情報源: NESdev Wiki（https://www.nesdev.org/wiki/）

## 1. 背景・目的

project.md は「キーボードで操作できること」「キーバインディングの変更ができること（GUI + 設定ファイル）」を要求している。
本書は NES 側のコントローラハードウェアの仕様を整理し、キーマッピング設計の前提を確定させる。

## 2. I/O ポートの構造

NES は本体前面に汎用コントローラポートを 2 個持ち、底面にほとんど使われなかった 48 ピン拡張ポートを持つ。
Famicom はコントローラが本体直結で、15 ピン拡張ポートがサードパーティ製コントローラに使われた。AV Famicom は NES と同じ着脱式。

I/O ポートの構成:

- **出力ポート 1 個、3 bit 幅**: $4016 への書き込みの下位 3 bit をラッチする。ラッチされた値は 2A03/07 の OUT0–OUT2 ピンに出る。OUT0 がコントローラポートへ、OUT0–OUT2 が NES の拡張ポートへ
- **入力ポート 2 個、各 5 bit 幅**: $4016 と $4017 の下位 5 bit を読む。$4016 の読み出しが /OE1、$4017 の読み出しが /OE2 をアサートする

| 本体 | D0 | D1 | D2 | D3 | D4 |
|---|---|---|---|---|---|
| NES コントローラポート | ○ | – | – | ○ | ○ |
| NES 拡張ポート | ○ | ○ | ○ | ○ | ○ |
| 初代 Famicom | $4016 D0/D2 と $4017 D0 が本体コントローラに直結 | 拡張ポート | マイク（$4016 のみ） | 拡張ポート | 拡張ポート |
| AV Famicom コントローラポート | ○ | – | – | – | – |

データラインの用途:

| ライン | 使用デバイス |
|---|---|
| D0 | NES 標準コントローラ、Famicom 本体直結コントローラ |
| D1 | Famicom 拡張ポートコントローラ |
| D2 | Famicom マイク（コントローラ 2 のみ） |
| D3 | Zapper の光センサ |
| D4 | Zapper のトリガ |

**Four Score（NES 4 人用アダプタ）は接続されたコントローラの D0 だけを通す。**

## 3. 読み取り手順

標準的な手順:

1. $4016 に 1 を書いてコントローラに入力をポーリングさせる
2. $4016 に 0 を書いてポーリングを終える
3. $4016 または $4017 から 1 bit ずつ読み出す

### 3.1 $4016 書き込み

```
 7  bit  0
 ---- ----
 xxxx xEES
       |||
       ||+- コントローラポートのラッチビット（strobe）
       ++-- 拡張ポートのラッチビット
```

下位 3 bit がラッチされ保持される。その他のビットは無視される。

**S（strobe）が high の間、コントローラ内部のシフトレジスタはボタン状態から継続的にリロードされ続ける。** この間 $4016/$4017 を読むと最初のボタン（A）の現在状態が返り続ける。S が low になるとリロードが止まる。したがって **1 → 0 の書き込みシーケンスが必要。**

### 3.2 $4016 / $4017 読み出し

```
 7  bit  0
 ---- ----
 xxxD DDDD
 |||+-++++- 入力データライン D4 D3 D2 D1 D0
 +++------- オープンバス
```

- 読み出しはコントローラポートの CLK ラインにクロックパルスを送り、接続された入力ラインから 1 bit を読む
- **$4016 はポート 1 のみ、$4017 はポート 2 のみ**（ポーリングは両方 $4016 への書き込みで行う）
- **読み値は反転される**: データラインの high は 0 として、low は 1 として読まれる

### 3.3 標準コントローラのレポート

8 bit を D0 に 1 bit ずつ返す（1 = 押されている）。

```
 0 - A
 1 - B
 2 - Select
 3 - Start
 4 - Up
 5 - Down
 6 - Left
 7 - Right
```

- **8 bit 読み終えた後は、Nintendo 純正コントローラなら以降すべて 1 を返す。** サードパーティ（U-Force など）は 0 を返すことがある
- **コントローラが接続されていないとき、対応するステータスビットは 0 を返す**（内部プルアップ抵抗と内部インバータのため）

### 3.4 未接続データラインとオープンバス（重要）

**NES / Famicom では上位 3 bit（Famicom では 5 bit）が駆動されず、バス上の直前のバイトのビットが残る。** 通常これはコントローラポートのアドレス上位バイト = `$40`。

**Paperboy など一部のゲームは、コントローラポートの読み出しが正確に $40 または $41 を返すことに依存している。** Mindscape 製のゲーム（Captain Planet, Dirty Harry, Infiltrator, Mad Max, Paperboy, The Last Starfighter）は「ボタンが押されたと認識するには $41 でなければならない」。

→ **実装必須**: $4016/$4017 の読み出しでは下位 5 bit だけをデバイスから取り、上位 3 bit は直前のバス値（= オープンバスラッチ）から取る。

### 3.5 CLK のタイミング

CLK ラインは `R/W NAND (アドレス == $4016/$4017)`（R/W が high = read なので、$4016/$4017 の読み出し中だけ CLK が low）。

- high → low の遷移で、NES 内部のバッファがコントローラのデータラインの出力をラッチする
- low → high の遷移で、コントローラ内のシフトレジスタが 1 bit シフトする

### 3.6 DPCM 競合（実装必須）

**DMC DMA が走っていて、CPU が $4016/$4017 を読もうとしたのと同じサイクルでリードを開始すると、読み値が無効になる。** アドレスバスが 1 サイクル変化するため、シフトレジスタが余分な立ち上がりエッジ（"ダブルクロック"）を見て 1 bit 落とす。プログラムからはシリアルデータの 1 bit 欠落として見える。

- 最もよく現れる症状は「**Right が勝手に押される**」。1 bit 欠落により余分な 1 bit が Right の位置に現れる
- 回避策: ゲーム側で「同じ結果が 2 回連続で得られるまで読み直す」のが一般的
- **2A07（PAL）ではこの問題が修正されている**

→ 詳細は `07_timing_and_synchronization.md`。

### 3.7 ターボコントローラ

NES Max や NES Advantage のようなターボコントローラは標準コントローラと同じように読まれるが、一部のボタンが 15〜30 Hz の発振器でトグルされる。

**コントローラは strobe パルスごとにボタン状態をトグルしてはいけない。** そうすると「同じ結果が 2 回連続で得られるまで読む」ループを持つゲームがハングしたりクラッシュしたりする。

→ エミュレータでターボ機能を実装するなら、**トグルは実時間（またはフレーム）ベースで行い、strobe ベースにはしない。**

## 4. ハードウェアの実体（4021 シフトレジスタ）

標準コントローラは 4021（8 bit パラレル→シリアルシフトレジスタ）を 1 個使う。

| ピン | 役割 |
|---|---|
| OUT（`$4016:0`） | 4021 の Parallel/Serial 制御。high でボタン 8 個の現在状態をレジスタに取り込む |
| CLK | 4021 のクロック入力。low→high でレジスタを 1 bit 上位へシフト。通常 high に保たれ、$4016/$4017 の読み出し中に low になる |
| D0 | 4021 の Q8 出力（レジスタ最終ビットの現在状態）。**NES はこの信号を反転する**ので、4021 側では未押下 = 1 だが CPU からは 0 に見える |
| GND | Vss。かつ Serial In にも接続されているので、クロックされるたびに空きビットに 0 がシフトインされる。**これが「8 個読み終えたら以降すべて 1 が返る」理由**（反転後） |

8 本の PI パラレル入力ピンはそれぞれ約 10 kΩ のプルアップで +5V に。ボタンを押すと GND に落ちる。**PI-8 が最初に読まれるボタン = A。**

### 4.1 PAL 固有の注意

一部の PAL リージョン本体（FRA, HOL, NOE）はコントローラポートに保護ダイオードを持つ。このダイオードは Clock と Latch 信号を high に引き上げないと機能させない。該当リージョンの PAL コントローラ（NES-004E）は各々 3.6 kΩ の抵抗をこの 2 本の入力と 5V の間に持つ。

→ エミュレータには影響しないが、実機での互換性の話として記録する。

## 5. Famicom 固有

- **初代 Famicom の本体直結 2P コントローラには Select と Start がない。** 対応ビットは 0 として読まれる。Famicom ゲームは 2P が Start/Select を押せることに依存してはいけない
- この 2P コントローラはマイクを内蔵しており、**$4016 D2 を読むと即座に 1 bit のレポートが返る**。Famicom ゲームは「レポートが 0→1 / 1→0 と変化したこと」を追跡するのが普通だった（特定の状態がマイク動作を表すことに依存しない）。マイクの音声そのものは APU 出力に混ぜられてカートリッジエッジに送られる（拡張音源が混ぜられる前）
- Famicom の拡張ポートに接続する外部コントローラは、標準の 8 bit レポートを **D0 ではなく D1** で返す。Famicom ゲームは D1 と D0 を OR して読むのが一般的だった（拡張コントローラも使えるようにするため）。ただし対応していないゲームもある

## 7. 実装方針と、その理由

### 7.1 デバイス抽象化

```go
// 概念スケッチ
type InputDevice interface {
    // $4016 への書き込み（下位 3 bit）
    Strobe(value uint8)
    // $4016 / $4017 の読み出し。下位 5 bit のみを返す
    Read() uint8
}
```

- ポート 1 / ポート 2 にそれぞれ 1 個の `InputDevice` を差す
- **上位 3 bit のオープンバス合成はポートの外側（バス層）で行う**（§3.4）
- 標準コントローラは「8 bit のシフトレジスタ + strobe 中の継続リロード」を素直に実装する。**「読み出しカウンタで何番目か数える」実装にすると strobe high 中の挙動を再現できない**

### 7.2 キーバインディング

project.md の要件を満たすため:

- 論理ボタン（A / B / Select / Start / Up / Down / Left / Right）× プレイヤー（1P / 2P）の 16 個を「アクション」として定義する
- 1 アクションに複数の物理キーを割り当てられる（キーボードとゲームパッドの併用）
- 設定ファイルには物理キーの**プラットフォーム非依存な識別子**で保存する（`12_config_and_packaging.md` で形式を決める）
- ターボ（連射）は「アクションごとの連射レート」オプションとして持つ。実時間ベースでトグルする（§3.7）

デフォルトのキー割り当て案（一般的な慣習に合わせる）:

| NES ボタン | 1P デフォルト | 2P デフォルト |
|---|---|---|
| Up / Down / Left / Right | ↑ ↓ ← → | W / S / A / D |
| A | X | G |
| B | Z | F |
| Start | Enter | R |
| Select | 右 Shift | T |

> なぜこれが使いやすいのか: 十字キーは方向キーに素直に対応し、A/B は右手の届きやすい隣接キー（Z/X）に置く。多くの NES エミュレータがこの配置を採っているので、ユーザーが乗り換えたときに学習しなおす必要がない。**ただし A と B の順序（Z=B, X=A）は左右の物理配置と NES コントローラの物理配置（B が左、A が右）を一致させている点が重要**で、逆にすると操作感が崩れる。

### 7.3 入力のサンプリングタイミング

GUI フレームワークのイベントループとエミュレーションループは別スレッドになる可能性が高い。

- キーの押下状態は**アトミックなビットマスク**として共有する
- エミュレータは「$4016 に 1 が書かれた瞬間」に現在のビットマスクを読む（実機の挙動に一致）
- フレーム単位でスナップショットを取る方式（多くのエミュレータがやる）でもほとんどのゲームは動くが、**1 フレーム内に複数回ポーリングするゲームのために、実機どおり strobe 時に読む**
