# CPU（Ricoh 2A03 / 6502 コア）調査

> 調査日: 2026-09-20 / 一次情報源: NESdev Wiki（https://www.nesdev.org/wiki/）、6502_cpu.txt（64doc）
> 本書は「ハードウェアの事実」をまとめたものであり、既存エミュレータの実装を参照していない（クリーンルーム）。

## 1. 背景・目的

Shogun Emulator の CPU コアを実装するための基礎資料。とくに次の判断に使う。

- CPU をサイクル単位（cycle-accurate）で回すか、命令単位（instruction-accurate）で回すか
- 命令デコード表をどういうデータ構造で持つか
- 非公式命令（undocumented opcode）をどこまで実装するか
- 割り込みのタイミングをどう表現するか

結論を先に書くと、**サイクル単位（1 CPU サイクル = 1 メモリアクセス）でバスアクセスを刻む方式**を採る。理由は §11 に書いた。

## 2. チップ概要

NES の CPU は MOS 6502 の第二ソース版で、Ricoh が製造した。

| 項目 | NTSC | PAL | Dendy（PAL famiclone） |
|---|---|---|---|
| チップ名 | RP2A03 | RP2A07 | UMC UA6527P |
| カラーサブキャリア f_sc | 3579545.4545… Hz (315/88 MHz) | 4433618.75 Hz | 4433618.75 Hz |
| マスタークロック 6·f_sc | 21.477272 MHz | 26.601712 MHz | 26.601712 MHz |
| 分周比 d | 12 | 16 | 15 |
| CPU クロック 6·f_sc/d | 1.789773 MHz（約 559 ns/cycle） | 1.662607 MHz（約 601 ns/cycle） | 1.773448 MHz（約 564 ns/cycle） |

重要な性質:

- **10 進モード（BCD）が無効化されている。** D フラグ自体は存在し、読み書き・スタック経由の保存もできるが、ADC/SBC の演算結果には一切影響しない。つまり ADC/SBC は常に 2 進演算。
- **6502 の 1 サイクルは必ず「1 回のリード」または「1 回のライト」である。** アイドルサイクルは存在せず、何もしないサイクルでも必ずどこかのアドレスを読む（ダミーリード）。この性質が PPU/APU レジスタの副作用に影響する（§9.4）。
- 非公式命令の挙動に 2A03 と 2A07 の差はない。
- CPU はマスタークロックを分周して自分のクロックを作る。PPU との比は NTSC で 1:3（CPU 1 サイクル = PPU 3 ドット）、PAL で 1:3.2。
- エミュレータ実装上の小技として、NTSC を 21441960 Hz（= (341×262−0.5)×4×60）で回すと、フレームレートがちょうど 60 fps に固定されて安定する、という知見が NESdev フォーラムにある（本来は 60.0988 Hz）。オーディオとディスプレイの同期方針として選択肢になる（→ `07_timing_and_synchronization.md`）。

## 3. レジスタ

| レジスタ | 幅 | 説明 |
|---|---|---|
| A | 8 bit | アキュムレータ。ALU に直結しており、演算命令のほとんどは A を対象にする |
| X | 8 bit | インデックスレジスタ。`(d,X)`（indexed indirect）を使えるのは X のみ |
| Y | 8 bit | インデックスレジスタ。`(d),Y`（indirect indexed）を使えるのは Y のみ |
| PC | 16 bit | プログラムカウンタ |
| S | 8 bit | スタックポインタ。スタックは $0100–$01FF に固定され、S はその下位 8 bit。下方向に伸びる |
| P | 8 bit | ステータスレジスタ。実体は 6 個の 1 bit レジスタ |

汎用レジスタ群（R0…R7 のようなもの）は存在しない。これは「ゼロページを疑似レジスタとして使う」という 6502 特有のプログラミングスタイルにつながっており、エミュレータのデバッガでもゼロページを特別扱いすると便利（→ `11_debugger_features.md`）。

### 3.1 P レジスタ（ステータスフラグ）

```
 7  bit  0
 ---- ----
 NV1B DIZC
 |||| ||||
 |||| |||+- C: Carry
 |||| ||+-- Z: Zero
 |||| |+--- I: Interrupt Disable
 |||| +---- D: Decimal
 |||+------ B: Break（CPU 内部には存在しない。スタックに積まれる値にのみ現れる）
 ||+------- 未使用（常に 1 として push される）
 |+-------- V: Overflow
 +--------- N: Negative
```

| フラグ | 挙動 |
|---|---|
| C | ADC の桁上がり。SBC/CMP では「借りが発生しなかった」= `A >= memory`。シフト/ローテートでは押し出されたビット。INC/DEC は C を変えない。SEC/CLC で直接操作 |
| Z | 値を生成するほとんどの命令で「結果 == 0」 |
| I | セット中は IRQ を抑止。NMI・BRK・リセットには効かない。割り込み受理時に P を push した後で自動的にセットされる。**SEI/CLI/PLP による変更は 1 命令ぶん遅れて効く**（§9.2） |
| D | NES では演算に影響しない。値の保存用として使える（実際に使うゲームは稀） |
| V | ADC/SBC の符号付きオーバーフロー。BIT は memory の bit 6 をそのまま V に入れる。CLV でクリアのみ可能（SEV は存在しない。2A03 は 6502 の SO ピンを外部に出していない） |
| N | 値を生成するほとんどの命令で「結果の bit 7」。BIT は memory の bit 7 をそのまま N に入れる |

**B フラグ（bit 4）は CPU 内部にレジスタとして存在しない。** P がスタックに積まれるとき、その原因によって値が決まる。

| push の原因 | B の値 |
|---|---|
| NMI | 0 |
| IRQ | 0 |
| BRK | 1 |
| PHP | 1 |

bit 5 は常に 1 として push される。スタックから pull するとき（PLP / RTI）、bit 5 と bit 4 は無視される（対応するレジスタがないため）。

> 実装メモ: デバッガで P を 8 bit 表示するとき、bit 5・bit 4 に決まった慣習はない。Shogun Emulator では **P を内部的に 6 個の bool として持ち、push 時に B を引数で与える**設計にする。表示時は `NV-BDIZC` 形式で、実機に存在しないビットは `-` を出す。

## 4. CPU メモリマップ

| アドレス範囲 | サイズ | デバイス |
|---|---|---|
| $0000–$07FF | $0800 | 内蔵 RAM 2 KiB |
| $0800–$0FFF | $0800 | $0000–$07FF のミラー |
| $1000–$17FF | $0800 | 同上 |
| $1800–$1FFF | $0800 | 同上 |
| $2000–$2007 | $0008 | PPU レジスタ |
| $2008–$3FFF | $1FF8 | $2000–$2007 のミラー（8 バイトごとに繰り返し） |
| $4000–$4017 | $0018 | APU および I/O レジスタ（2A03 内蔵） |
| $4018–$401F | $0008 | 通常は無効化されている APU/IO テスト機能 |
| $4020–$FFFF | $BFE0 | 未割り当て。カートリッジが自由に使う |

内蔵 RAM の慣習的な用途:

- `$0000–$00FF` ゼロページ。他のアドレスより 1 バイト・1 サイクル短くアクセスできる
- `$0100–$01FF` スタックページ。通常 $01FF から下方向に使う
- `$0200–$02FF` が OAM バッファ（VBlank 中に OAM DMA で転送する 256 バイト）として使われることが非常に多い

カートリッジ側の慣習:

- `$6000–$7FFF` バッテリーバックアップ SRAM またはワーク RAM（WRAM / PRG-RAM）
- `$8000–$FFFF` PRG-ROM とマッパーレジスタ

割り込みベクタ（カートリッジが供給する）:

| アドレス | 用途 |
|---|---|
| $FFFA–$FFFB | NMI ベクタ |
| $FFFC–$FFFD | リセットベクタ |
| $FFFE–$FFFF | IRQ / BRK ベクタ |

バンク切り替えを行うマッパーでは、ベクタを含む領域（通常 $C000–$FFFF）を固定バンクにするか、全バンクにベクタとリセットスタブを置く必要がある。エミュレータ側の含意は「**ベクタ読み出しもマッパー経由の通常のリードとして処理する**」こと。特別扱いしてはいけない。

その他の重要な性質:

- CPU レジスタ（$4000–$401F）のアドレスデコードは**完全デコード**されている（PPU レジスタやマッパーレジスタと違いミラーしない）。
- カートリッジは CPU アドレス空間全体のリード/ライトを観測できる。ただし $4015 のリードだけは CPU 内部で完結するため観測できない。
- 2A03 のレジスタデコードの癖により、$4000–$401F のリード中に CPU が停止（RDY low）すると DMA が誤動作する。このためカートリッジは読み出し可能なメモリを $4020–$FFFF にのみ置くことが推奨される。
- 未割り当て領域のリードは**オープンバス**を返す。詳細は `07_timing_and_synchronization.md` のオープンバス節を参照。
- DMC のサンプルデータは実用上 `$C000–$FFF1` に置かれる（$FFFF から $8000 へラップする）。

## 5. アドレッシングモード

### 5.1 インデックス付きアドレッシング

| 略記 | 名称 | 実効アドレス | サイクル |
|---|---|---|---|
| `d,X` | Zero page indexed | `(arg + X) & $FF` | 4 |
| `d,Y` | Zero page indexed | `(arg + Y) & $FF` | 4 |
| `a,X` | Absolute indexed | `arg + X` | 4+ |
| `a,Y` | Absolute indexed | `arg + Y` | 4+ |
| `(d,X)` | Indexed indirect | `PEEK16((arg + X) & $FF)`（ゼロページ内でラップ） | 6 |
| `(d),Y` | Indirect indexed | `PEEK16(arg) + Y`（ポインタ読み出しはゼロページ内でラップ） | 5+ |

`+` は「ページ境界をまたいだリードのとき、または書き込み命令のとき 1 サイクル追加」を意味する。この追加サイクルを 64doc では "oops cycle" と呼んでいる。

**oops サイクルの正体**: 6502 は 8 bit ALU を 1 個しか持たないため、`a,X` の実効アドレスを計算するとき、まず下位バイトだけを加算し（同時に上位バイトをフェッチする）、キャリーが出たら「間違ったアドレス（$100 だけ小さいアドレス）から一度リードしてしまう」。その後キャリーを適用して正しいアドレスで読み直す。

- **リード命令**: ページ境界をまたいだときだけ余分な 1 サイクル（と不正アドレスからのダミーリード）が発生する
- **ストア命令（STA/STX/STY）**: 書き込みは取り消せないため、**必ず**不正アドレスからダミーリードしてから正しいアドレスに書く。よってページ境界に関係なく常に 5 サイクル
- `(d),Y` も同じ構造を持つ

> これはエミュレータで無視できない。ダミーリードが PPU レジスタや MMC3 の A12 カウンタを叩くケースが実際に存在する。

### 5.2 その他のアドレッシング

| 略記 | 名称 | 説明 |
|---|---|---|
| （なし） | Implicit | RTS, CLC など。オペランドを持たない |
| `A` | Accumulator | `LSR A` など。A を対象にする |
| `#v` | Immediate | オペランドそのものを値として使う |
| `d` | Zero page | 8 bit アドレス |
| `a` | Absolute | 16 bit アドレス |
| `label` | Relative | 分岐命令。次の命令の先頭を基準とした符号付き 8 bit オフセット |
| `(a)` | Indirect | JMP のみ。16 bit ポインタが指す先へジャンプ |

**JMP (a) のバグ**: ポインタのアドレス下位バイトが $FF のとき、上位バイトのインクリメントが行われない。`JMP ($03FF)` は $03FF と **$0300** を読む（$0400 ではない）。この挙動は実装必須。

`*` は「ページ境界をまたいだら +1 サイクル」。

#### ロード / ストア

| LDX | $A2/2/2 | $A6/2/3 | – | $B6/2/4 | $AE/3/4 | – | $BE/3/4* | – | – |
| LDY | $A0/2/2 | $A4/2/3 | $B4/2/4 | – | $AC/3/4 | $BC/3/4* | – | – | – |
| STA | – | $85/2/3 | $95/2/4 | – | $8D/3/4 | $9D/3/5 | $99/3/5 | $81/2/6 | $91/2/6 |

#### 演算 / 論理 / 比較

| 命令 | # | d | d,X | a | a,X | a,Y | (d,X) | (d),Y | 影響フラグ |
|---|---|---|---|---|---|---|---|---|---|
| ADC | $69/2/2 | $65/2/3 | $75/2/4 | $6D/3/4 | $7D/3/4* | $79/3/4* | $61/2/6 | $71/2/5* | N V Z C |
| SBC | $E9/2/2 | $E5/2/3 | $F5/2/4 | $ED/3/4 | $FD/3/4* | $F9/3/4* | $E1/2/6 | $F1/2/5* | N V Z C |
| AND | $29/2/2 | $25/2/3 | $35/2/4 | $2D/3/4 | $3D/3/4* | $39/3/4* | $21/2/6 | $31/2/5* | N Z |
| ORA | $09/2/2 | $05/2/3 | $15/2/4 | $0D/3/4 | $1D/3/4* | $19/3/4* | $01/2/6 | $11/2/5* | N Z |
| EOR | $49/2/2 | $45/2/3 | $55/2/4 | $4D/3/4 | $5D/3/4* | $59/3/4* | $41/2/6 | $51/2/5* | N Z |
| CMP | $C9/2/2 | $C5/2/3 | $D5/2/4 | $CD/3/4 | $DD/3/4* | $D9/3/4* | $C1/2/6 | $D1/2/5* | N Z C |
| CPX | $E0/2/2 | $E4/2/3 | – | $EC/3/4 | – | – | – | – | N Z C |
| CPY | $C0/2/2 | $C4/2/3 | – | $CC/3/4 | – | – | – | – | N Z C |
| BIT | – | $24/2/3 | – | $2C/3/4 | – | – | – | – | N(=M7) V(=M6) Z |

- ADC: `A = A + M + C`。`C = (result > $FF)`、`V = (result ^ A) & (result ^ M) & $80`
- SBC: `A = A + ~M + C`（= `A - M - ~C`）。`C = 借りなし`、`V = (result ^ A) & (result ^ ~M) & $80`
- CMP/CPX/CPY は減算を行うがレジスタも V も変更しない
- BIT は Z を `A & M` で決め、N と V には M の bit 7 / bit 6 を**そのまま**入れる

## 7. 非公式命令（undocumented opcodes）

**エミュレータは 256 個すべての opcode を実装しなければならない。** 6502 のマイクロコードは 130 エントリのデコード ROM に圧縮されており、未使用 opcode は「無関係な複数のマイクロコード行を同時に起動する」ため、明確な（ただし文書化されていない）動作をする。

実際に非公式命令を使う市販ゲームの例:

| ゲーム | opcode |
|---|---|
| Beauty and the Beast (E) | $80（2 バイト NOP） |
| Disney's Aladdin (E) | $07（SLO） |
| Dynowarz: Destruction of Spondylus | $DA, $FA（1 バイト NOP） |
| F-117A Stealth Fighter / Infiltrator / Puzznic | $89（2 バイト NOP） |
| Ninja Jajamaru-kun | $04（2 バイト NOP） |
| Super Cars (U) | $B3（LAX） |
| 文字广场+排雷（2-in-1 多カート） | $8B（XAA）まで正しく実装しないとリセットハンドラに到達しない |

ホームブリューでは MUSE サウンドエンジン（$8F SAX / $B3 LAX / $CB AXS）など、より積極的に使われている。

### 7.1 opcode 完全マップ（256 エントリ）

### 7.2 安定した非公式命令の意味

RMW 系（ALU 演算と RMW 演算の合成）。いずれも「RMW を実行したうえで、その結果に対して ALU 演算を行う」。対応する ALU 命令と同じアドレッシングモードを持ち、RMW 命令なのでライトが 2 回発生する。

| 命令 | 動作 | opcode（(d,X) / d / a / (d),Y / d,X / a,Y / a,X） |
|---|---|---|
| SLO | `ASL memory` → `ORA memory` | $03/$07/$0F/$13/$17/$1B/$1F |
| RLA | `ROL memory` → `AND memory` | $23/$27/$2F/$33/$37/$3B/$3F |
| SRE | `LSR memory` → `EOR memory` | $43/$47/$4F/$53/$57/$5B/$5F |
| RRA | `ROR memory` → `ADC memory` | $63/$67/$6F/$73/$77/$7B/$7F |
| DCP | `DEC memory` → `CMP memory` | $C3/$C7/$CF/$D3/$D7/$DB/$DF |
| ISC | `INC memory` → `SBC memory` | $E3/$E7/$EF/$F3/$F7/$FB/$FF |

サイクル数は (d,X)=8 / d=5 / a=6 / (d),Y=8 / d,X=6 / a,Y=7 / a,X=7。**a,X・a,Y・(d),Y ではページ境界をまたがなくても常にペナルティサイクルが付く**（ストア命令と同様）。

ロード / ストア系:

| 命令 | 動作 | opcode | サイクル |
|---|---|---|---|
| LAX | `LDA` + `TAX`（A と X に同時にロード） | (d,X)=$A3/6, d=$A7/3, a=$AF/4, (d),Y=$B3/5*, d,Y=$B7/4, a,Y=$BF/4* | |
| SAX | `memory = A & X`（フラグ変化なし） | (d,X)=$83/6, d=$87/3, a=$8F/4, d,Y=$97/4 | |

`LAX #i` に相当する $AB は不安定（下記 XAA と同系）。

即値系:

| 命令 | opcode | 動作 |
|---|---|---|
| ALR #i | $4B | `AND #i` → `LSR A`。N Z C を更新。別名 ASR |
| ANC #i | $0B, $2B | `AND #i` してから N（bit 7）を C にコピー |
| ARR #i | $6B | `AND #i` → `ROR A`。ただし **C = 結果の bit 6、V = bit 6 XOR bit 5**。N Z は通常どおり |
| AXS #i | $CB | `X = (A & X) - i`（借りなし）。N Z C を更新。V は変化しない。別名 SBX |
| SBC #i | $EB | 公式の $E9 と同一動作 |

NOP 系:

| 分類 | opcode | バイト | サイクル | 動作 |
|---|---|---|---|---|
| 1 バイト NOP | $1A, $3A, $5A, $7A, $DA, $FA（+公式 $EA） | 1 | 2 | 何もしない |
| 2 バイト NOP（SKB / DOP） | $80, $82, $89, $C2, $E2 | 2 | 2 | 即値を読み捨てる |
| IGN d | $04, $44, $64 | 2 | 3 | ゼロページを読んで捨てる（副作用なし） |
| IGN d,X | $14, $34, $54, $74, $D4, $F4 | 2 | 4 | `d` と `(d+X)&$FF` の両方を読む |
| IGN a | $0C | 3 | 4 | 絶対アドレスを読んで捨てる（PPU レジスタの副作用を起こせる） |
| IGN a,X | $1C, $3C, $5C, $7C, $DC, $FC | 3 | 4* | a,X のページ境界ペナルティあり |

「読んで捨てる」命令もリードサイクルが発生するので、**PPUSTATUS のラッチリセットや PPUADDR のインクリメントを起こす**。副作用を無視して実装すると一部 ROM が壊れる。

### 7.3 不安定な非公式命令

| 命令 | opcode | 動作 |
|---|---|---|
| SHX a,Y | $9E | `STX a,Y` の壊れた版。書き込む値が `X & (アドレス上位バイト + 1)` になる。ページ境界をまたぐ場合、計算後アドレスの上位バイトも X と AND される。4 サイクル目に DMC DMA で割り込まれると（RDY が low になると）挙動が変わる |
| SHY a,X | $9C | SHX の X/Y を入れ替えたもの |
| AHX (d),Y / a,Y | $93, $9F | `memory = A & X & (アドレス上位バイト + 1)`。別名 SHA |
| TAS a,Y | $9B | AHX と TXS の合成。X の代わりに `A & X` を使う。`S = A & X` も行う。別名 SHS |
| XAA #i | $8B | `A = (A \| $EE) & X & i` 相当。実機では内部の定数 $11 が $10 / $01 / $00 になることがあり、**アナログ的な要因（データバスに残った値）に依存する**。別名 ANE |
| LAX #i | $AB | `A = X = (A & i)` 相当だが XAA と同様に不安定。別名 LXA |
| LAS a,Y | $BB | `A = X = S = memory & S`。別名 LAE |
| STP | $02, $12, $22, $32, $42, $52, $62, $72, $92, $B2, $D2, $F2 | CPU を停止させる。リセットしないと復帰しない。別名 JAM / KIL |

**実装方針**: 安定な命令は完全に実装する。不安定な命令（XAA / LAX# / TAS / AHX / SHX / SHY / LAS）は「一般に観測されている挙動」を実装し、デバッグログに警告を出す。STP は「CPU 停止」状態にして、デバッガに「STP により停止」と表示する（無限ループにしてハングさせない）。

## 8. サイクル単位のバス動作

64doc（6502_cpu.txt）に記載されている、アドレッシングモードごとの 1 サイクル = 1 バスアクセスの内訳。**この表が CPU 実装のコア仕様になる。**

前提:

- NMOS 6500 系は 1 命令につき必ず 2 回以上のリードを行う（opcode と、その次のバイト）
- パイプライン的動作: 最終サイクルでメモリに書き込まない命令は、最終サイクルと同時に次の opcode をフェッチできる。だから `EOR #$FF` は実質 3 サイクルの動作だが 2 サイクル命令として数える
- RMW 命令は「未変更の値を書く → 変更後の値を書く」（INC は実質 `LDX loc; STX loc; INX; STX loc`）
- 書き込みサイクル中は RDY が無視される（連続ライトは最大 3 回。これは割り込みシーケンスで起こる）
- インデックス付きアドレッシングでページ境界をまたぐとき、プロセッサはまず「1 ページ小さい不正なアドレス」を読む

### 8.1 Implied / Accumulator

```
 #  address R/W description
 1    PC     R  opcode をフェッチ、PC++
 2    PC     R  次の命令バイトを読んで捨てる
```

### 8.2 Immediate

```
 1    PC     R  opcode をフェッチ、PC++
 2    PC     R  値をフェッチ、PC++
```

### 8.3 Zero page

```
リード（LDA/LDX/LDY/EOR/AND/ORA/ADC/SBC/CMP/BIT/LAX/NOP）
 1    PC      R  opcode
 2    PC      R  アドレスをフェッチ、PC++
 3  address   R  実効アドレスからリード

RMW（ASL/LSR/ROL/ROR/INC/DEC/SLO/SRE/RLA/RRA/ISC/DCP）
 1    PC      R  opcode
 2    PC      R  アドレスをフェッチ、PC++
 3  address   R  リード
 4  address   W  元の値を書き戻す（同時に演算を行う）
 5  address   W  新しい値を書く

ライト（STA/STX/STY/SAX）
 1    PC      R  opcode
 2    PC      R  アドレスをフェッチ、PC++
 3  address   W  レジスタを書く
```

### 8.4 Zero page indexed（`d,X` / `d,Y`）

```
リード

 2     PC       R  アドレスをフェッチ、PC++
 3   address    R  address からリード（この値は捨てる）し、インデックスを加算
 4  address+I*  R  実効アドレスからリード
     * 実効アドレスの上位バイトは常に $00（ページ境界のラップは処理されない）

RMW（X のみ）
 1..4 上と同じ
 5  address+X*  W  元の値を書き戻す（演算）

ライト
 1     PC       R  opcode
 2     PC       R  アドレスをフェッチ、PC++
 3   address    R  address からリード（捨てる）、インデックス加算
 4  address+I*  W  実効アドレスに書く
```

JMP

 3    PC      R  下位を PCL にコピーしつつ、アドレス上位を PCH にフェッチ

リード
 1    PC      R  opcode
 2    PC      R  アドレス下位、PC++
 3    PC      R  アドレス上位、PC++
 4  address   R  実効アドレスからリード

RMW
 1..4 上と同じ

ライト

### 8.6 Absolute indexed（`a,X` / `a,Y`）

```
リード
 1     PC       R  opcode
 2     PC       R  アドレス下位、PC++
 3     PC       R  アドレス上位をフェッチ、下位にインデックスを加算、PC++
 4  address+I*  R  実効アドレスからリード、上位バイトを修正
 5+ address+I   R  実効アドレスから再リード
     * この時点で上位バイトは不正（$100 小さい）ことがある
     + サイクル 4 でアドレスが不正だった場合（ページ境界をまたいだ場合）のみ実行

RMW
 1..4 上と同じ（X のみ）
 5  address+X   R  再リード
 6  address+X   W  元の値を書き戻す（演算）
 7  address+X   W  新しい値を書く
     → ページ境界と無関係に常に 7 サイクル

ライト（STA/STX/STY/AHX/SHX/SHY）
 1..3 上と同じ
 4  address+I*  R  実効アドレスからリード（ダミー）、上位バイトを修正
 5  address+I   W  実効アドレスに書く
     → 書き込みは取り消せないため、常に先にリードする（常に 5 サイクル）
```

### 8.7 Relative（分岐）

```
 1     PC       R  opcode
 2     PC       R  オペランドをフェッチ、PC++
 3     PC       R  次の命令の opcode をフェッチ。
                   分岐する場合はオペランドを PCL に加算。しない場合は PC++
 4+    PC*      R  次の命令の opcode をフェッチ。PCH を修正。変化しなければ PC++
 5!    PC       R  次の命令の opcode をフェッチ、PC++
     + 分岐が成立した場合に実行
     ! 別ページに分岐した場合に実行
     * この時点で PCH は不正（$100 大きい/小さい）ことがある
```

サイクル 3 以降の「次の opcode フェッチ」は図示のためのもので、実行時間を数えるときは最後のサイクルを引く。したがって分岐命令は 2 / 3 / 4 サイクル。

## 9. 割り込み

### 9.1 検出メカニズム

- **NMI はエッジ検出**（high → low の遷移に反応）。**IRQ はレベル検出**（low の間ずっと反応）。両方とも負論理。
- NMI のエッジ検出器は、各 CPU サイクルの φ2（サイクルの後半）で NMI 線の状態をサンプリングする。前サイクルで high、次サイクルで low なら内部信号を立てる。内部信号はエッジ検出の次のサイクルの φ1 で high になり、**NMI が処理されるまで high のまま**。
- IRQ のレベル検出器は、あるサイクルの φ2 で low を検出すると、次サイクルの φ1 で内部信号を立てる。その信号は**そのサイクルの間だけ** high。
- 検出器の出力は特定のタイミングでポーリングされる。ほとんどの命令では**命令の最終サイクル**（次の opcode フェッチの前）にポーリングされる。
- 「割り込みは命令の最終サイクルでポーリングされる」という説明は検出器の出力についてのみ正しい。実際に効くのは**最後から 2 番目のサイクルの終わりにおける割り込み線の状態**である。
- NMI と IRQ が同時に pending なら NMI が処理され、IRQ の pending 状態は忘れられる（ただし IRQ はレベル検出なので次のポーリングで再検出されるのが普通）。
- 割り込みシーケンス自体はポーリングを行わない。よって**割り込みハンドラの最初の 1 命令は必ず実行される**。

### 9.2 CLI / SEI / PLP による遅延

- **RTI は即時**に I フラグを反映する。IRQ が pending の状態で RTI が I をクリアすると、RTI 終了直後に IRQ ハンドラに入る。RTI は割り込みポーリングより前に I を復元するため。
- **CLI / SEI / PLP は、割り込みポーリングの後に** I を変更する（2 サイクル命令はすべて 1 サイクル目の終わりでポーリングする）。したがってこれらは割り込みを次の命令の後まで遅らせる効果を持つ。たとえば IRQ が pending で I がセットされているとき、CLI を実行すると**次の 1 命令が実行された後**に IRQ ハンドラに入る。

### 9.3 分岐命令の割り込みポーリング

分岐命令の挙動は微妙。

- 2 番目の CPU サイクル（オペランドフェッチ）の前には必ずポーリングされる
- 分岐が成立した場合の 3 番目のサイクルの前ではポーリングされない
- 分岐が成立してページ境界をまたぐ場合、PCH 修正サイクルの前にもポーリングされる
- これらのポーリング点のいずれか（最初の 1 つだけでも）で検出されれば割り込みが発生する

### 9.4 割り込みハイジャック

BRK 実行中の最初の 4 tick の間に NMI がアサートされると、BRK は途中まで普通に実行される（PC のインクリメントは起き、B フラグはセットされたまま P が push される）が、**ジャンプ先が NMI ベクタになる**。

```
各 [] は 1 CPU tick。* の区間で NMI をアサートすると NMI ルーチンに飛ぶ。

     ********************
[...][BRK][BRK][BRK][BRK][BRK][BRK][BRK]
```

同様に NMI は IRQ を、IRQ は BRK をハイジャックできる。IRQ が NMI にハイジャックされても通常は問題ない（NMI から戻ったときに IRQ がまだアサートされていて再度割り込みが発生する）。しかし **BRK は NMI/IRQ によって実質的にキャンセルされうる**。スタックの B ビットを見れば NMI ハンドラ側で検出できる。

この挙動は `cpu_interrupts_v2` テスト ROM で検証できる（→ `08_test_roms_and_validation.md`）。

## 10. 電源投入・リセット時の状態

計測は 1988 年製 NTSC フロントローダー（RP2A03G、NES-CPU-07 基板）で行われたもの。

| レジスタ | 電源投入時 | リセット後 |
|---|---|---|
| A, X, Y | 0 | 不変 |
| PC | ($FFFC) | ($FFFC) |
| S | $00 − 3 = $FD | S −= 3 |
| C, Z, D, V, N | 0 | 不変 |
| I | 1 | 1 |

リセットは NMI/IRQ/BRK と同じロジックを使うが、2A03 はリセット中の**ライトを禁止**する。そのため S は 3 回デクリメントされるがメモリは書き換わらない。I は必ずセットされる。

RAM の内容:

- 内蔵 RAM（$0000–$07FF）とカートリッジ RAM は電源投入時に**不定**。リセットでは変化しない。
- エミュレータは一貫した初期状態（全 $00、全 $FF、特定のパターンなど）を実装することが多い
- バッテリーバックアップ SRAM も初回電源投入時は不定

**Shogun Emulator の方針**: 設定で「$00 / $FF / ランダム / 特定パターン」を選べるようにし、デフォルトは開発者向けにランダム + 「未初期化 RAM 読み出しでブレーク」オプションを用意する。実機再現性より「ゲームのバグを踏んだときに気づけること」を優先する。

## 11. 実装方針と、その理由

### 11.1 サイクル単位で回す

命令単位（1 命令実行 → その命令のサイクル数だけ PPU/APU を進める）方式のほうが実装は速くて簡単だが、次が再現できない。

1. **命令の途中で起こる PPU/APU レジスタアクセスの副作用**。特に `a,X` のダミーリードが $2007 や MMC3 の A12 を叩くケース
2. **RMW 命令の二重ライト**（`INC $2007` など）
3. **DMA と CPU の相互作用**（OAM DMA、DMC DMA が CPU を特定のサイクルで止める）
4. **スプライト 0 ヒットやスキャンライン IRQ のサイクル単位の観測**

よって「1 CPU サイクル = 1 バスアクセス」を単位とし、`read(addr)` / `write(addr, value)` が呼ばれるたびに PPU を 3 ドット、APU を 1 サイクル進める設計にする。

### 11.1.1 実装スタイル: 自然なコード + tick コールバック（セーブステートの制約）

サイクル単位で回す方法は 2 つある。

| 方式 | スナップショット粒度 | 実装コスト |
|---|---|---|
| 明示的ステートマシン（全状態がフィールド） | 任意のサイクル | 大（コード量 2〜3 倍） |
| **自然なコード + tick コールバック（採用）** | **命令境界のみ** | 小（§8 の表と 1 対 1 対応） |

**採用理由**: §8 の tick 単位の表をそのままコードにできるため、`nestest.log` との突き合わせで誤りを特定しやすい。セーブステートは命令境界で取れれば十分である。

**制約**: サイクル単位ステップ実行の途中ではスナップショットが取れない（状態がホストのコールスタックにあるため）。**セーブステート要求は命令境界まで実行してから処理し、UI に明示する。**

詳細と、この方式を選んだ根拠は `14_savestate_and_movie.md` §3 にある。

### 11.2 命令テーブルの持ち方

opcode 256 個の配列に「アドレッシングモード」「演算」「アクセス種別（read / write / rmw / implied）」を持たせ、
アドレッシングモードごとのサイクルシーケンス（§8）を共通コードとして実装する。
これにより非公式命令が「既存のアドレッシングモード × 既存の演算の組み合わせ」としてほぼ自動的に正しいサイクル数になる。

### 11.3 割り込みの表現

- `nmiLine` の前回値を保持し、立ち下がりで `nmiPending = true`（エッジ検出）
  - **`nmiLinePrev` と `nmiPending` はセーブステートに含める**（`14` §4.1）
- `irqLine` は「IRQ 源の OR」を毎サイクル評価（レベル検出）
- 各命令の最後から 2 番目のサイクル終わりで `pollInterrupts()` を呼び、結果を `interruptDelayed` に記録
- CLI / SEI / PLP は「ポーリング後にフラグを変更」する順序を守る
- ハイジャックは「ベクタを決めるのはサイクル 5 の直前」という 1 箇所で実装する
