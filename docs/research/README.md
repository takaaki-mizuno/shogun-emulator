## 本プロジェクトの方針

### 一次情報源

**NESdev Wiki（https://www.nesdev.org/wiki/）を一次情報源とする。** これは NES/Famicom ハードウェアのリバースエンジニアリング結果を 20 年以上蓄積したコミュニティの成果で、Visual 2C02 / Visual 2A03 のトランジスタレベルシミュレーションに裏付けられた記述が多い。

加えて次を参照した。

- `6502_cpu.txt`（64doc）— 6502 のサイクル単位のバス動作
- `christopherpow/nes-test-roms` — テスト ROM とその readme
- Go module proxy（`proxy.golang.org`）— ライブラリの最新バージョンの実測
- 各 Go ライブラリの公式ドキュメント・README・GitHub Issues

### クリーンルーム方針（project.md のルール）

project.md は「既存の NES エミュレータ実装は参考にしない。既存のコードを参照しない、いわゆるクリーンルーム設計（知的財産権の回避）で設計、実装を行う」と定めている。

本調査では:

- ✅ **ハードウェアの仕様書・解析文書**（NESdev Wiki、データシート、Visual 2C02 の解析結果）を参照した
- ✅ **テスト ROM とその readme**（合否判定プロトコルの仕様）を参照した
- ✅ **GUI フレームワーク・オーディオライブラリのドキュメント**（NES エミュレータとは無関係）を参照した
- ❌ **既存 NES エミュレータのソースコードは一切参照していない**

NESdev Wiki には「FCEUX ではこの変数を `PPUGenLatch` と呼ぶ」のような他実装への言及があるが、これは**ハードウェアの性質を説明するための用語の紹介**であり、実装の参照ではない。

### ドキュメントの書き方

各ドキュメントは次の構成を持つ。

1. **背景・目的** — なぜこの調査が必要か、どの判断に使うか
2. **調査結果** — ハードウェアの事実。表とビット図で機械的に読める形にする
3. **実装方針と、その理由** — 事実からどう設計を決めたか。**「なぜそうするのか」を必ず書く**
4. **未解決・後続調査** — チェックボックス付き
5. **参考資料** — URL と参照日

「調べた事実の羅列で終わらせず、必ず判断を書く」ことを守っている。**判断を書いておかないと、後から読んだ開発者（AI でも人間でも）が同じ検討をやり直すことになる。**

## 決定事項（2026-09-21）

| 項目 | 決定 | 根拠 |
|---|---|---|
| GUI フレームワーク | **Fyne v2.8.1** | `09_go_gui_frameworks.md` §0 |
| オーディオ | **oto v3.5.1**（48 kHz / 16bit ステレオ / 50 ms バッファ） | `10_audio_and_video_output.md` §4 |
| デバッグビューア | **別ウィンドウと 1 ウィンドウ内タブの両方をサポート**（デフォルトは別ウィンドウ） | `09_go_gui_frameworks.md` §0 |
| シングルバイナリ | **OS 標準ランタイムへの依存は許容** | 同上 |
| コンポーネント同期 | **lock-step**（CPU 1 サイクル = PPU 3 ドット = APU 1 サイクル） | `07_timing_and_synchronization.md` §7.1 |
| 実時間同期 | **オーディオ駆動（バックプレッシャ方式）**。リング高水位でエミュレータをブロックする。壁時計ティッカーは使わない | `09a` §4.4 の 60 秒耐久試験で確定 |
| スコープ | **セーブステート・入力ムービー・巻き戻しを第 1 弾に含める** | `14` §1（人間の判断） |
| CPU の実装方式 | **自然なコード + tick コールバック。スナップショットは命令境界のみ** | `14` §3。明示的ステートマシンは実装コストが 2〜3 倍で、得られる「任意サイクル保存」は §3.3 の規則で代替できる |
| 決定論 | map のイテレーション・ゴルーチン・壁時計・グローバル乱数をエミュレーションから排除。不定値はすべてシード化して記録 | `14` §6 |

スパイクで検証済み（`09a_fyne_performance_spike.md`）:

- Fyne の実ペイントは **60.00 fps**（768×720）、**59.83 fps**（1536×1440）。拡大率による劣化なし
- oto は **20 ms バッファでもアンダーランなし**。ただし**駆動方式が重要**で、ティッカー駆動は 60 秒で音切れ 137 回、バックプレッシャ方式は 0 回
- 別ウィンドウ 3 枚、`container.AppTabs`、ネイティブメニュー、`TextGrid` のセル単位の色付け — すべて動作確認済み
- **Fyne v2.8 のスレッドモデル**（`fyne.Do` / `fyne.DoAndWait` 必須）という設計に影響する事実を発見
