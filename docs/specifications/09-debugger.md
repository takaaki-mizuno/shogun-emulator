# 09 デバッガ設計

- 文書バージョン: 1.0
- 作成日: 2026-09-21
- 対象システム: Shogun Emulator（将軍エミュレータ）

---

## 9.1 構成

デバッガは `internal/debug` に置く。エミュレーションコアに `Hooks`（「02 エミュレーションコア設計」§2.9）を設定し、そこから状態を取り出す。

```go
package debug

type Debugger struct {
    nes *nes.NES

    breakpoints *BreakpointSet
    tracer      *Tracer
    disasm      *Disassembler
    changes     *ChangeTracker
    snapshots   *SnapshotSet
}
```

デバッガは `Bus.Peek` と `Bus.Poke` のみを使う。`Bus.Read` と `Bus.Write` を呼ばない。表示のためにレジスタの副作用を発生させないためである。

## 9.2 変更追跡

メモリのどのバイトが最近書き換わったかを記録する。

フレームが完成するたびに、追跡対象の現在の内容を前のフレームの内容と比べ、値が変わったバイトの `lastWrite` を現在のフレーム番号にする。書き込みのフックで記録しないのは次の理由による。

| 理由 |
|---|
| 色の濃さはフレーム単位で決まるため、フレーム末の比較で時間の分解能は変わらない |
| 同じ値の書き込み（毎フレームの初期化など）で色が付かず、実際に変わったバイトだけが目立つ |
| OAM DMA や PPU の内部更新のように CPU のバスを通らない変更も捉えられる |
| バスアクセスごとの費用がかからない |

```go
type ChangeTracker struct {
    mu           sync.Mutex
    lastWrite    [regionCount][]uint32 // 変わったフレーム番号 + 1。0 は変わっていない
    prev         [regionCount][]uint8  // 前のフレームの内容
    currentFrame uint32
    decayFrames  uint32                // 何フレームで色が消えるか
}

// Heat は 0.0 から 1.0 を返す。1.0 が直前のフレームで変わったことを表す。
func (t *ChangeTracker) Heat(r Region, offset int) float32
```

`Update` はエミュレーションゴルーチンから、`Heat` と `HeatRow` は UI スレッドから呼ばれるため、`mu` で守る。`HeatRow` は 1 行分をまとめて返し、バイトごとにロックを取らない。

追跡の対象と容量を次に示す。1 バイトにつき、フレーム番号の 4 バイトと比較用の写しの 1 バイトを持つ。

| 領域 | 対象 | 容量 |
|---|---|---|
| `RegionRAM` | 内蔵 RAM | 2 KiB × 5 バイト |
| `RegionCIRAM` | CIRAM | 4 KiB × 5 バイト |
| `RegionOAM` | OAM | 256 × 5 バイト |
| `RegionPalette` | パレット RAM | 32 × 5 バイト |
| `RegionPRGRAM` | PRG-RAM | カートリッジの PRG-RAM の大きさ × 5 バイト |

PRG-RAM が 8 KiB のカートリッジで合計約 73 KiB となる。ROM を読み込んだとき、巻き戻したとき、ステートを読み込んだときに記録を空にする。

時間で減衰させるのは、1 フレームだけ色を変える方式では人間の目に映らず、書き換えたまま色を残す方式では画面全体が色付くためである。`decayFrames` の既定値は 30 とする。

## 9.3 スナップショット

ビューアが参照するメモリを、フレーム末または指定したスキャンラインの開始時にコピーして UI スレッドへ渡す。

```go
type Snapshot struct {
    Frame      uint64
    Scanline   int             // 取ったスキャンライン。フレーム末は -1
    CHR        [8192]uint8     // PPU の $0000-$1FFF（現在のバンク構成で読んだ値）
    Nametables [4096]uint8     // PPU の $2000-$2FFF（ミラーリングを通した値）
    CIRAM      [4096]uint8
    OAM        [256]uint8
    Palette    [32]uint8
    Ctrl, Mask uint8           // $2000 と $2001 の値
    ScrollV    uint16          // フレームの描画開始時の v（「04 PPU 設計」§4.10.1）
    FineX      uint8
    Mirroring  cart.Mirroring
    CPUState   cpu.State
    BankView   []cart.BankView // CHR のバンク構成
    SpriteHeight int           // 8 または 16
    ScanlineSpriteCount [240]uint8 // 行ごとの範囲内のスプライト数
    SpriteDrawn [64]bool       // 描かれたスプライト
}

type SnapshotSet struct {
    mu       sync.Mutex
    complete *Snapshot
    working  *Snapshot
}
```

コピーする総量は 17 KiB 程度である。60 fps で毎秒 1 MiB となる。

`ScanlineSpriteCount` と `SpriteDrawn` はコピーした OAM と `SpriteHeight` から求める。各行について、範囲内のスプライトを OAM の順に最大 8 個まで描かれたものとし、9 個目以降は描かれないものとする。9 以上の行はスプライトオーバーフローが起きる行である。フレームの途中で OAM を書き換えるプログラムでは、実際に描かれたものと一致しない場合がある。

### 9.3.1 取得位置の購読

MMC3 などがスキャンラインごとに CHR バンクを切り替える場合、フレーム末の状態は画面の一部しか表さない。ビューアはスナップショットを取る位置を購読する。

```go
// AcquireSnapshots は line の開始時（-1 でフレーム末）に取るスナップショットを
// 購読する。同じ位置の購読は 1 つの SnapshotSet を共有する。
func (d *Debugger) AcquireSnapshots(line int) *SnapshotSet

// ReleaseSnapshots は購読をやめる。最後の購読をやめた位置では取らない。
func (d *Debugger) ReleaseSnapshots(s *SnapshotSet)
```

取得位置はビューアごとに独立して持つ。パターンテーブルビューアでステータスバー側のバンクを見ながら、ネームテーブルビューアでフレーム末の状態を見るためである。購読が 1 つも無いときスナップショットを作らず、そのためのフックも設定しない。フレーム末の購読があるときは `OnFrameComplete`、スキャンラインの購読があるときは `OnCycle` を使う。

## 9.4 ビューア

各ビューアは `fyne.CanvasObject` を返すコンポーネントとして実装し、配置形態を知らない（「10 GUI 設計」§10.2）。

| ビューア | 表示 | 編集 |
|---|---|---|
| パターンテーブル | 16×16 タイルのグリッド 2 面。各面 128×128 ピクセル | タイルを 8×8 のピクセルエディタで編集 |
| ネームテーブル | 4 面を 2×2（512×480 ピクセル）。現在のスクロール枠を重ねる | タイル番号と属性値を変更 |
| スプライト | 64 スプライトの一覧と各フィールドの数値 | 各フィールドを数値で編集 |
| パレット | パレット RAM 32 エントリと 64 色の全パレット | エントリの色を 64 色から選択 |
| メモリ | 16 進ダンプ | 16 進の桁を直接編集 |
| 逆アセンブル | ニーモニックと現在位置 | プログラムのパッチ |
| CPU 状態 | レジスタ、スタック、コールスタック、保留中の割り込み | レジスタの値を編集 |
| APU 状態 | 5 チャンネルの現在値 | チャンネルのミュートとソロ |
| ログ | フィルタ付きのログ表示 | なし |

### 9.4.1 パターンテーブルビューア

タイルの並びは左から右、上から下とする。`$00` が左上、`$0F` が右上、`$FF` が右下に来る。

設定で 8×16 スプライト向けの並べ替えを選べる。1 行目を `$00, $02, …, $1E`、2 行目を `$01, $03, …, $1F` とする。

適用するパレットを選択できる。選択肢はグレースケール・背景 0–3・スプライト 0–3 とし、既定値はグレースケール（パレットを適用しない）とする。タイルの形を確認しやすい。

マウスオーバーでタイル番号・CHR アドレス・現在のバンク番号と CHR 上のオフセットを表示する。現在のバンク構成（`Info().CHRBanks`）を一覧で表示する。

拡大率を 1 倍から 8 倍で変更できる。

タイルをクリックすると 8×8 のピクセルエディタを開く。エディタは選択中のパレットの色で表示し、4 色（色 0 と 3 色）から描く色を選ぶ。ドラッグで連続して描け、元に戻す操作を持つ。書き込みは 1 ピクセルごとに PPU アドレスの 2 バイト（下位プレーンと上位プレーン）へ行う（§9.4.8）。

### 9.4.2 ネームテーブルビューア

4 面を 2×2（512×480 ピクセル）で表示する。`$2000`–`$2FFF` をミラーリングを通して読むため、現在のミラーリング設定が反映され、同一の内容が 2 箇所に表示される。背景のパターンテーブルは `$2000` の bit 4 に従う。

現在のスクロール枠（256×240）を線で重ねる。枠の左上は `Snapshot.ScrollV` と `FineX` から求める。

| 成分 | 値 |
|---|---|
| X | `(v >> 10 & 1) × 256 + (v & 0x1F) × 8 + fineX` |
| Y | `(v >> 11 & 1) × 240 + (v >> 5 & 0x1F) × 8 + (v >> 12 & 7)` |

枠が 512×480 の右端または下端をまたぐときは、左端・上端へ折り返して分割して描く。

オーバーレイとして次を切り替えられる。

| オーバーレイ |
|---|
| スクロール枠 |
| 属性グリッド（16×16 ピクセル単位） |
| タイルグリッド（8×8 ピクセル単位） |

マウスオーバーでネームテーブルアドレス・タイル番号・属性値・適用パレットを表示する。タイルをクリックするとタイル番号を変更するダイアログを開き、パターンテーブルの 256 タイルから選ぶ。右クリックで、その位置を含む 16×16 の属性領域のパレット番号（0–3）を変更する。

### 9.4.3 スプライトビューア

各スプライトについて、インデックス・Y・タイル番号・属性・X を数値で表示する。属性はパレット番号・優先度・水平反転・垂直反転に分解して示す。8×16 モードでは 2 タイル分を描画する。反転を反映して描く。

スプライト 0 を強調表示する。タイミング源として用いられるためである。描かれなかったスプライト（`SpriteDrawn` が false）を薄く示す。

スキャンラインごとのスプライト数を表示する。9 個以上の行を強調する。

メイン画面にスプライトの矩形を重ねるオプションを持つ。重ねる位置はスナップショットの OAM から求め、ビューアを更新するたびに合わせる。

スプライトを画面上の位置に描いた 256×240 の配置図を持つ。配置図でクリックすると、その位置にある最も手前（OAM の番号が小さい）のスプライトを選ぶ。選んだスプライトの各フィールドを数値で編集できる。配置図でドラッグすると、動かした量だけ X と Y を変える。

### 9.4.4 パレットビューア

パレット RAM 32 エントリを背景 4 組とスプライト 4 組に分けて表示する。backdrop 色（`$3F00`）を明示する。各エントリにアドレスと値（`$00`–`$3F`）を示す。

`$3F00` と `$3F10` が同一の記憶域を指すことを表示に反映する。片方を変更するともう片方も変わる。`$3F04`・`$3F08`・`$3F0C` と `$3F14`・`$3F18`・`$3F1C` も同じである。

64 色の全パレットを 4×16 のグリッドで表示する。`$0D` に使用非推奨の印を付ける。

エンファシス（R・G・B）とグレースケールを選んで適用した結果をプレビューできる。既定値は現在の `$2001` の値とする。

エントリをクリックすると 64 色から選ぶダイアログを開き、選んだ色をパレット RAM へ書く。

### 9.4.5 メモリビューア

```
        00 01 02 03 04 05 06 07  08 09 0A 0B 0C 0D 0E 0F
$0000:  00 01 A5 FF 00 00 00 00  12 34 56 78 00 00 00 00
```

`widget.TextGrid` を用い、セル単位に前景色と背景色を設定する。`TextGrid` は入力を受け取らないため、タップ・ホイール・キー入力を受け取るウィジェットで包み、`CursorLocationForPosition` でタップした位置の行と桁を求める。表示するのは見えている行だけであり、その範囲だけを副作用なしに読む（`Bus.Peek`・`PPU.PeekVRAM`）。表示のために `$2002` を読んでも VBlank フラグは消えない。

| 表示 | 色 |
|---|---|
| PC が指すバイト | 黄色の背景 |
| スタックポインタが指す位置 | 青の背景 |
| 最近書き換わったバイト | 赤の背景。`ChangeTracker.Heat` の値で濃さを決める |
| 選んでいるバイト | 灰色の背景 |
| ゼロページとスタックページの境界 | 区切り線 |

色が重なるときは、選んでいるバイト・PC・スタックポインタ・変更の順に優先する。PC は CPU アドレス空間と PRG-ROM（`PRGOffset` で求めた位置）に、スタックポインタは CPU アドレス空間と内蔵 RAM に示す。

表示対象の空間を切り替えられる。

| 空間 | 範囲 |
|---|---|
| CPU アドレス空間 | `$0000`–`$FFFF` |
| 内蔵 RAM | `$0000`–`$07FF`（ミラーを畳む） |
| PPU アドレス空間 | `$0000`–`$3FFF` |
| OAM | `$00`–`$FF` |
| PRG-ROM | ファイル上のオフセット |
| CHR-ROM | 同上 |
| PRG-RAM | `$6000`–`$7FFF` |

1 行のバイト数を 8・16・32 から選べる。既定値は 16 とする。

編集は `Bus.Poke` を用いる。設定（`debug.memoryEditWrite`）で `Bus.Write` を用いる動作（副作用あり）も選べる。レジスタへの書き込みを試すために用いる。バイトを選んで 16 進の桁をタイプすると、上位の桁、下位の桁の順に書き換え、下位の桁を書いたら次のバイトへ進む。PRG-ROM と CHR-ROM への書き込みはオーバーレイへ行う（§9.4.8）。ムービーの記録中と再生中は編集を断る。記録した入力と結果の対応が崩れるためである。

バイト列と文字列の検索、アドレスのウォッチリスト、アドレスへの名前付けを行える。検索はカーソルの次の位置から後ろを探し、見つからなければ先頭へ折り返す。ウォッチと名前は CPU アドレスで持ち、CPU アドレス空間・内蔵 RAM・PRG-RAM の表示から付ける。名前は ROM ハッシュごとにファイルへ保存する（§9.9）。

メモリビューアは複数開ける。CPU 空間と PPU 空間を同時に見るためである。

### 9.4.6 逆アセンブルビューア

```
        C000  4C F5 C5     JMP $C5F5
>       C5F5  A2 00        LDX #$00
        C5F7  86 00        STX $00
   *    C5F9  86 10        STX $10
```

`>` が現在の PC、`*` がブレークポイントを表す。現在の行は黄色の背景とし、PC が上から 1/3 あたりに来るよう開始位置を選ぶ。

CPU デバッガは逆アセンブルに次を並べる。

| 表示 | 内容 |
|---|---|
| レジスタ | A・X・Y・PC・S・P。P は `NV-BDIZC` の形でも示す。値を編集できる |
| 位置 | 累積 CPU サイクル数、フレーム、スキャンライン、ドット。命令の途中で止まっているときはその位置 |
| 保留中の割り込み | NMI と、IRQ の発生源（APU フレーム・DMC・マッパー） |
| スタック | `$01FF` から S+1 までの内容 |
| コールスタック | JSR と割り込みで積んだ呼び出し。推定である旨を示す |
| 実行制御 | 実行・停止・サイクル・命令・オーバー・アウト・スキャンライン・フレーム・カーソルまで・ブレークポイントの切り替え |
| ブレークポイント | 一覧、追加、削除、有効の切り替え、条件式の編集 |

逆アセンブルの行をタップすると、その行をカーソルにする。「カーソルまで」と「ブレークポイントの切り替え」はカーソルのアドレスを対象とする。コールスタックを推定とするのは、スタックを直接書き換えるプログラムや RTS による間接ジャンプを JSR と RTS の対応から区別できないためである。

| 表示 |
|---|
| アドレス、機械語バイト列、ニーモニック、オペランド |
| 非公式命令を別色で表示し、別名を併記する |
| 分岐先とジャンプ先に名前が付いていれば名前を表示する |
| 実効アドレスとその現在値をコメントとして表示する |

命令境界の決定を次の順で行う。

1. 実行済みのアドレスを記録する。実行されたバイトを命令の先頭として確定する
2. 未実行の領域は先頭から線形に逆アセンブルし、確定していない旨を薄い色で示す
3. 利用者が領域をコードまたはデータとして指定できる。指定は ROM ハッシュごとにファイルへ保存する

実行済みアドレスの記録は PRG-ROM のファイルオフセットで行う。バンク切り替えにより同じ CPU アドレスが複数のバンクを指すためである。

### 9.4.7 APU 状態ビューア

「05 APU 設計」§5.9 の `Inspect` の値を表示する。チャンネルごとのミュートとソロを持つ。ソロは他の 4 チャンネルをミュートすることで実現する。ミュートは出力段（`SetMute`）だけで扱い、エミュレーション状態を変えない。オーディオのリングバッファの充填量と高水位を表示する。

### 9.4.8 編集

ビューアからの書き込みはすべて `Emulator.Poke` を通す。ムービーの記録中と再生中は断る。

| 書き込み先 | 反映先 |
|---|---|
| CHR（CHR-ROM） | オーバーレイ（「06 カートリッジとマッパー設計」§6.8）。PPU アドレスを現在のバンク構成で CHR-ROM のオフセットに直して書く |
| CHR（CHR-RAM） | CHR-RAM へ直接 |
| ネームテーブル | ミラーリングを通して CIRAM へ直接 |
| パレット | パレット RAM へ直接。上位 2 bit は 0 にする |
| OAM | OAM へ直接 |
| PRG-ROM | オーバーレイ |

オーバーレイの有効・無効はデバッグメニューから切り替える。無効にすると ROM の元の内容に戻る。編集したオーバーレイは ROM を閉じるときとアプリケーションを終了するとき、および編集の操作を終えるたびに保存し、ROM を読み込んだときに読み込む。

## 9.5 実行制御

```go
type StepKind uint8

const (
    StepCycle StepKind = iota
    StepInstruction
    StepOver
    StepOut
    StepScanline
    StepFrame
    RunToCursor
)
```

| 操作 | 動作 |
|---|---|
| `StepCycle` | 1 CPU サイクル進める |
| `StepInstruction` | 1 命令実行する |
| `StepOver` | JSR のときは対応する RTS まで実行する |
| `StepOut` | 現在のサブルーチンから RTS するまで実行する |
| `StepScanline` | 次のスキャンラインの先頭まで実行する |
| `StepFrame` | 次のフレームの先頭まで実行する |
| `RunToCursor` | 指定アドレスに達するまで実行する |

`StepCycle` は `Hooks.OnCycle` で実現する。フックは CPU サイクルの終わりに呼ばれ、停止が要求されていれば `internal/emu` の中でチャネル待ちに入る。`internal/nes` は並行処理の仕組みを持たないため（「01 全体アーキテクチャ設計」§1.7）、待ちはフックの側に置く。

命令の途中で止まっている間は、コマンドキューを処理できない。この間に届いたサイクル単位ステップ以外のコマンドは、待ちを解いて命令を最後まで実行させてから、命令境界で処理する。

`StepOver` は JSR を実行する前のスタックポインタを覚え、RTS でスタックポインタがその値に戻った命令境界で止まる。`StepOut` は現在のスタックポインタより 2 大きい値に戻る RTS まで実行する。いずれもスタックポインタの深さで判定するため、割り込みの RTI で戻る場合も同じ判定で止まる。

`StepCycle` で命令の途中に止まっている状態ではセーブステートを取れない。扱いは「08 セーブステートと入力ムービー設計」§8.3.2。

## 9.6 ブレークポイント

```go
type BreakKind uint8

const (
    BreakExec BreakKind = iota
    BreakRead
    BreakWrite
    BreakPPUPosition
    BreakEvent
)

type Breakpoint struct {
    Kind      BreakKind
    AddrStart uint16
    AddrEnd   uint16    // 範囲。単一アドレスなら AddrStart と同じ
    Scanline  int       // BreakPPUPosition
    Dot       int       // BreakPPUPosition
    Event     EventKind // BreakEvent
    Condition *Condition
    Enabled   bool
    HitCount  uint64
}

type EventKind uint8

const (
    EventNMI EventKind = iota
    EventIRQ
    EventReset
    EventSprite0Hit
    EventMapperIRQ
    EventUninitializedRAMRead
    EventMMC3IRQReloadWithoutClocks
)
```

`EventSprite0Hit` は画面分割の調査に用いる。`EventUninitializedRAMRead` は内蔵 RAM のうち書き込みが行われていないアドレスの読み出しを検出する。書き込みの記録は、このブレークポイントを有効にした時点か電源投入の時点の新しい方から始まる。記録を始める前に書かれたアドレスは未初期化として扱う。`EventMMC3IRQReloadWithoutClocks` は `$C001`（`$C000`–`$DFFF` の奇数）への書き込みが、前回の書き込みから A12 の立ち上がり 2 回を挟まずに行われたことを検出する。立ち上がりの回数は MMC3 が数えた値を使う。

ブレークポイントで止まる位置を次に示す。

| 種別 | 止まる位置 |
|---|---|
| `BreakExec` | 指定アドレスの命令を実行する前の命令境界 |
| `BreakRead`・`BreakWrite` | アクセスした命令を終えた命令境界 |
| `BreakPPUPosition` | 指定したドットを含む CPU サイクルの終わり（命令の途中） |
| `BreakEvent` | イベントが起きた命令を終えた命令境界 |

PPU 位置ブレークポイントがドットではなく CPU サイクルの単位で止まるのは、CPU と PPU を 1 CPU サイクルごとに進めているためである。1 CPU サイクルの中の特定のドットでは止められない。

ブレークポイントが 1 つも有効でないとき、条件の評価を行わない。`BreakpointSet` が種別ごとの有効件数を保持し、`Hooks` の設定を切り替える。

### 9.6.1 条件式

```go
type Condition struct {
    Expr string        // "A == $42 && X < $10"
    prog []instruction // 解析結果
}
```

文法を次のとおり定める。

| 要素 | 記法 |
|---|---|
| レジスタ | `A`, `X`, `Y`, `S`, `PC`, `P` |
| フラグ | `C`, `Z`, `I`, `D`, `V`, `N` |
| メモリ | `[$0300]`、`[$0300+X]` |
| 数値 | `$42`（16 進）、`42`（10 進）、`%1010`（2 進） |
| 比較 | `==`, `!=`, `<`, `<=`, `>`, `>=` |
| 論理 | `&&`, `\|\|`, `!` |
| 括弧 | `(`, `)` |

メモリ参照は `Bus.Peek` を用いる。

## 9.7 トレース

```go
package cpu

// TraceRecord はトレースの 1 命令分。32 バイトに収める。
type TraceRecord struct {
    Cycles   uint64
    PC       uint16
    Scanline int16
    Dot      int16
    A, X, Y  uint8
    P, S     uint8
    Bytes    [3]uint8 // 命令のバイト列
    Reads    [3]uint8 // 注記のために読んだ値
}

package debug

type Tracer struct {
    ring  []cpu.TraceRecord // リングバッファ
    next  int
    count uint64
    out   *bufio.Writer     // 常時出力の出力先。nil のとき出さない
}
```

`Hooks.OnBeforeExec` から命令の実行前に記録する。記録は値のコピーだけとし、文字列への整形は書き出すときに `TraceRecord.Line` で行う。命令ごとに文字列を作ると、トレースを有効にするだけで実行が遅れるためである。`Reads` は実効アドレスとその値の注記に使う値を、記録の時点で副作用なしに読んだものである。`Line` の出力は「03 CPU 設計」§3.8 の形式と一致する。

リングバッファに常に最新 N 命令を保持し、ブレークポイントで停止したときまたは要求されたときにファイルへ書き出す。`ringSize` の既定値は 1000000 とする。1 命令あたり 32 バイトとして 32 MiB を占める。書き出し先はトレースの保存先（「11 設定と CLI 設計」§11.2）の `<ROM 名>-<累積サイクル数>.log` とする。

常時ファイルへ出力する動作も選べる。毎秒 30 万行程度になる。出力先は同じ保存先の `<ROM 名>-<累積サイクル数>-live.log` とし、64 KiB のバッファを通して書く。

## 9.8 ログ

```go
package debug

type Category uint32

const (
    CatTraceCPU Category = 1 << iota
    CatTraceCPUBus
    CatPPURegister
    CatPPUTiming
    CatAPURegister
    CatAPUFrame
    CatMapper
    CatDMA
    CatInput
    CatWarnCompat
    CatError
)
```

| カテゴリ | 内容 | 想定される量 |
|---|---|---|
| `trace.cpu` | 全命令のトレース | 毎秒約 30 万行 |
| `trace.cpu.bus` | 全バスアクセス | 毎秒約 180 万行 |
| `ppu.register` | PPU レジスタへのアクセス | 毎フレーム数百行 |
| `ppu.timing` | スキャンライン、VBlank、NMI | 毎フレーム数百行 |
| `apu.register` | APU レジスタへのアクセス | 毎フレーム数十行 |
| `apu.frame` | フレームカウンタ | 毎フレーム 4 行 |
| `mapper` | バンク切り替え、IRQ | 毎フレーム数十から数千行 |
| `dma` | OAM DMA、DMC DMA | 毎フレーム数行 |
| `input` | コントローラの読み取り | 毎フレーム数十行 |
| `warn.compat` | 実機で値が定まらない挙動への到達 | まれ |
| `error` | 内部エラー | まれ |

`warn.compat` に記録する対象を次に示す。

| 対象 |
|---|
| 不安定な非公式命令の実行 |
| STP の実行 |
| 色 `$0D` の使用 |
| レンダリング中の `$2007` アクセス |
| OAMADDR が 0 でない状態でのスプライト評価開始 |
| DMC DMA によるレジスタの多重読み出し |
| ヘッダのマッパー番号上位 4 bit のマスク |
| 4 画面を示すヘッダビットの無視 |
| セーブステートのオーバーレイハッシュ不一致 |

出力の判定は構造体のフィールドで行う。関数呼び出しを介さない。

```go
if d.log.Categories&CatPPURegister != 0 {
    d.log.PPURegister(addr, value)
}
```

`trace.cpu` の出力は専用のフォーマッタで行う。`log/slog` は毎秒 30 万行の出力には用いない。

出力先を `file`・`stdout`・`stderr` から選ぶ。ファイル出力ではサイズと世代数でローテーションする。

`warn.compat` と `error` は、同じ内容の記録を 3 回まで残し、4 回目に「以降は記録しない」旨を 1 行添えて、それ以降は出力にもログビューア向けの保持にも入れない。色 `$0D` の書き込みのように、同じ事象を毎フレーム繰り返すプログラムで出力が埋まるのを防ぐためである。覚えている内容が 1000 種類を超えたときと、ROM を読み込んだときに数え直す。他のカテゴリは同じ内容でも毎回記録する。同じレジスタへの毎フレームの書き込みを追うためである。

ログビューア向けに最新 10000 行を保持する。ログビューアは、表示するカテゴリの絞り込み、文字列の検索、表示行数の上限（既定値 1000、新しい行を優先）、記録するカテゴリの切り替えを持つ。記録するカテゴリの切り替えは `debug.logCategories` に反映する。

## 9.9 保存する状態

デバッガの状態はエミュレーション状態ではない。セーブステートに含めない。

次の項目を ROM ハッシュごとのファイルへ保存する。

| 項目 | ファイル |
|---|---|
| ブレークポイント | `symbols/<rom-hash>.json` |
| アドレスの名前 | 同上 |
| コードとデータの指定 | 同上 |
| ウォッチリスト | 同上 |
| CHR と PRG のオーバーレイ | `patches/<rom-hash>.json` |

引数 `--break-at` と設定 `debug.breakOnUninitializedRamRead` で置いたブレークポイントは一時的なものとし、保存しない。起動や ROM の読み込みのたびに置き直すためである。

保存するものが無いときはファイルを置かない。名前・指定・ウォッチ・ブレークポイントのいずれも持たないとき、およびオーバーレイが変更を持たず有効のときは、ファイルがあれば消す。ROM を開いただけで空のファイルを残さないためである。
